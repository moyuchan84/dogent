# 05. 스킬(SOP) 명세

> 문서 상태: v0.2 (2026-10-13) — 구현된 형식 기준. 실제 예시는 `skills/wip-check/`, `skills/firewall-request/`.

스킬은 업무 절차 하나를 에이전트가 따라 할 수 있게 적은 문서입니다. 현업 담당자가 직접 읽고 고칠 수 있어야 하므로 Markdown으로 씁니다.

설계의 기본 생각은 **모델에게 맡기는 판단을 최소로 줄이는 것**입니다. 무엇을 누를지, 단계가 끝났는지, 제출해도 되는지를 스킬 문서와 규칙이 정하고, 모델은 현재 화면에서 그 동작을 수행합니다. 작은 모델(gemma3:4b)로 시험했을 때 모델에게 판단을 맡긴 부분은 대부분 실패했고, 아래 형식으로 옮긴 뒤에 완주했습니다.

## 1. 파일 구조

```
skills/
  firewall-request/
    SKILL.md          # 스킬 본문 (필수)
    policy.yaml       # 입력값 규칙 (선택)
```

`skills/<id>/`에 넣고 빌드하면 사이드 패널의 스킬 목록에 나타납니다. 형식이 잘못되면 패널 상단에 오류가 표시되고 그 스킬은 목록에서 빠집니다.

## 2. 선언부 (YAML)

기계가 강제하는 부분입니다.

| 필드 | 필수 | 설명 |
|---|:-:|---|
| `id` | ● | 고유 식별자 (영문 소문자, 하이픈) |
| `name` | ● | 표시 이름 |
| `description` | ● | 언제 쓰는 스킬인지. 자연어 요청에서 스킬을 고를 때 쓰인다 |
| `version` | ● | 버전 (major.minor.patch) |
| `owner` | ● | 담당 부서/담당자 |
| `risk` | ● | 최고 위험 등급 (R0~R3). R3가 아니면 저장·상신 계열 버튼을 어느 단계에서도 누를 수 없다 |
| `domains` | ● | 접근 허용 도메인. 밖으로는 이동할 수 없고, 밖의 화면은 조작할 수 없다 |
| `inputs` |  | 입력 항목 (아래 표) |
| `submit_steps` |  | 저장·상신 버튼을 누를 수 있는 단계 번호. 다른 단계에서는 차단된다 |
| `submit_labels` |  | 승인 후 누를 수 있는 버튼 이름. 적으면 그 버튼만 가능 (예: `[상신]`이면 "임시 저장"은 차단) |
| `schedulable` |  | 스케줄 실행 허용 여부 (Phase 3) |
| `limits` |  | `max_steps` (기본 40), `timeout_sec` (기본 300) |

### 입력 항목

| 속성 | 설명 |
|---|---|
| `name` | 본문에서 `{name}`으로 참조하는 이름 |
| `label` | 폼과 오류 메시지에 보이는 이름 |
| `type` | `string`, `number`, `text`(여러 줄), `enum`, `ip`, `port`, `file` |
| `required` | 필수 여부 |
| `default` | 기본값 |
| `values` | `enum`의 선택지 |
| `dataset` | `file`일 때, 읽은 표를 담을 데이터셋 이름 |

`ip`는 IPv4 주소 또는 CIDR(`10.1.2.0/24`), `port`는 1~65535의 숫자 또는 범위(`8000-8010`)만 받습니다.

`file`은 xlsx 또는 csv 파일입니다. 첫 시트의 첫 행을 컬럼 이름으로 읽어 `dataset`에 적은 이름의 데이터셋으로 넣습니다. 파일은 사용자 PC에서 읽고, 내용은 모델에 보내지 않습니다(모델에는 컬럼 이름과 샘플 몇 행만 보임).

## 3. 본문

| 절 | 내용 |
|---|---|
| `## 단계` | 번호가 붙은 절차 (필수) |
| `## 판단 기준` | 업무 규칙 |
| `## 예외` | 상황별 대응. 적혀 있지 않은 상황은 중단하고 보고한다 |
| `## 결과` | 마지막 보고에 담을 내용 |

### 3.1 단계 쓰는 법

한 단계에는 다음 줄들이 올 수 있습니다.

```markdown
2. type으로 "출발지 IP"를 입력한다. args는 다음을 그대로 쓴다.
   `{"ref": "출발지 IP", "text": "{src_ip}"}`
   - 확인: "출발지 IP" 입력란에 값이 들어갔다.
   - 검사: value("출발지 IP") == "{src_ip}"
```

| 줄 | 읽는 쪽 | 역할 |
|---|---|---|
| 첫 줄 | 모델 | 무엇을 하는 단계인지 |
| `` `{...}` `` | 모델 | 도구에 넘길 인자. 모델은 그대로 복사한다 |
| `- 확인:` | 사람, 모델 | 단계가 끝난 상태에 대한 설명 |
| `- 검사:` | 루프 | 단계 완료를 규칙으로 판정하는 식. 모델에게는 보이지 않는다 |
| `- 기록:` | 루프 | 단계가 끝난 시점의 화면에서 값을 읽어 둔다. 모델에게는 보이지 않는다 (3.4절) |

**인자를 직접 적는 것을 권장합니다.** `ref`에는 화면에 보이는 요소 이름(라벨, 버튼 글자)을 적으면 루프가 현재 화면의 번호로 바꿉니다. 이름이 화면에 둘 이상이면 실행 전에 오류로 알려줍니다. 인자를 적지 않으면 모델이 화면을 보고 스스로 정합니다.

`{name}` 자리에는 입력값이 들어갑니다. 값이 없는 선택 입력은 `(미지정)`이 되고, `(미지정)`과 비교하는 검사는 통과로 봅니다(그 단계는 자동으로 건너뜀).

### 3.2 모델 없이 바로 실행되는 단계

단계의 첫머리가 **`도구로`** (`navigate로`, `click으로`, `type으로`, `select로`, `close_tab으로`, `extract_table로`, `download_table로`, `fill_table로`, `transform으로`, `write_excel로`, `finish로`)로 시작하고 `` `{...}` `` 인자가 적혀 있으면, 루프가 **모델을 부르지 않고** 그 동작을 그대로 실행합니다.

- 모든 단계를 이렇게 쓰면 스킬 전체가 모델 호출 없이 돕니다. 로컬 gemma3:4b로 약 4분 걸리던 재공 확인이 수 초에 끝나고, 결과도 매번 같습니다.
- 통제는 똑같이 적용됩니다. 허용 도메인, 저장·상신 승인, 제출 전 대조를 그대로 거칩니다.
- 단계마다 한 번만 시도합니다. 그 동작이 실패하거나(화면이 바뀌어 요소를 못 찾는 경우 등) 한 번으로 단계가 끝나지 않으면, 그 단계의 나머지는 모델이 화면을 보고 맡습니다. 모델은 평소에는 쓰이지 않고 **절차가 어긋났을 때의 복구**에 쓰입니다.
- 패널 설정의 "스킬에 인자가 적힌 단계는 모델 없이 바로 실행"을 끄면 모든 동작을 모델이 정합니다 (모델의 능력을 잴 때).

인자 안에서는 다음 자리표시자를 쓸 수 있습니다.

| 자리표시자 | 값 |
|---|---|
| `{입력이름}` | 스킬 입력값 |
| `{out.이름}` | 앞 단계의 `기록:`으로 화면에서 읽은 값 (3.4절) |
| `{rows.데이터셋}` | 데이터셋의 현재 행 수 |

### 3.3 검사 식

`- 검사:` 줄이 있는 단계는 **조건이 충족되는 순간 루프가 다음 단계로 넘기고**, 충족되기 전에는 모델이 건너뛸 수 없습니다. 이미 충족된 단계(예: 화면이 이미 열려 있음)는 모델을 부르지 않고 지나갑니다. 검사 줄이 없는 단계는 모델이 `next_step`으로 끝났다고 알려야 넘어갑니다.

| 식 | 뜻 |
|---|---|
| `text("글자")` | 화면에 그 글자가 보인다 |
| `no_text("글자")` | 화면에 그 글자가 없다 |
| `url("주소 일부")` | 열려 있는 화면(iframe 포함)의 주소에 그 글자가 들어 있다 |
| `value("요소 이름") == "값"` | 입력란·선택 상자의 현재 값이 같다 |
| `rows("데이터셋") == page_number("정규식")` | 데이터셋 행 수가 화면에서 읽은 숫자와 같다. 정규식의 첫 괄호가 숫자 (예: `"총 ([\d,]+)건"`) |
| `dataset("이름")` | 그 이름의 데이터셋이 있다 |
| `did("도구")` | 이 단계에서 그 도구가 한 번 이상 성공했다 |
| `dialog("글자")` | 이 단계에서 그 글자가 든 알림·확인 창이 떴다 (4.3절) |

여러 조건은 `and`로 잇습니다. 식이 잘못되면 스킬을 읽을 때 몇 단계의 오류인지 알려줍니다.

조회처럼 화면이 이전과 같아 보일 수 있는 동작에는 `did("click")`을 함께 씁니다. 예: `did("click") and no_text("조회 중") and text("총")`.

### 3.4 기록 식

신청 번호처럼 화면에 새로 나타난 값을 결과에 남길 때 씁니다. 모델이 옮겨 적다 틀릴 수 있는 값을 규칙으로 읽습니다.

```markdown
8. click으로 "상신" 버튼을 한 번 누른다. args는 다음을 그대로 쓴다.
   `{"ref": "상신"}`
   - 검사: did("click") and text("신청 번호")
   - 기록: request_id = page_text("신청 번호: (\S+)")
9. finish로 결과를 보고한다. args는 다음을 그대로 쓴다.
   `{"summary": "신청 번호 {out.request_id}로 접수되었습니다."}`
```

`이름 = page_text("정규식")` 형태이며, 정규식의 첫 괄호가 값이 됩니다. 뒤 단계에서 `{out.이름}`으로 쓸 수 있고, 실행 결과와 실행 기록에도 남습니다. 화면에서 찾지 못하면 `(화면에서 찾지 못함)`이 들어갑니다.

### 3.5 작성 규칙

1. **한 단계에 한 가지 동작.** "라인과 공정을 선택한다"는 두 단계로 나눈다. 작은 모델은 한 단계에 일이 둘이면 하나를 빠뜨린다.
2. **모든 단계에 검사 줄.** 마지막 보고 단계만 예외다.
3. 화면에 보이는 **라벨 그대로** 적는다. 좌표나 내부 ID는 적지 않는다.
4. 가공(`transform`)과 저장(`write_excel`)의 인자는 **스킬에 그대로 적는다.** 모델이 가공 명세를 직접 짜면 조건을 잘못 엮는 경우가 있었다.
5. 예외에 없는 상황은 **중단 후 보고**가 기본이다.

## 4. 도구

| 도구 | 인자 | 비고 |
|---|---|---|
| `navigate` | `url` | 허용 도메인만. 이미 열린 화면으로는 다시 이동하지 않는다 |
| `click` | `ref`, `row`, `accept_dialog` | 저장·상신 계열 버튼은 5절의 통제를 받는다. 새 창과 확인 창은 4.3절, 표 안의 요소는 4.4절 |
| `close_tab` | | 에이전트가 따라 들어간 새 창을 닫고 원래 창으로 돌아간다 (4.3절) |
| `type` | `ref`, `text`, `row` | 기존 값을 바꾼다 |
| `select` | `ref`, `value`, `row` | `value`는 화면에 보이는 옵션 글자 |
| `wait_for` | `text`, `timeout_sec` | |
| `extract_table` | `ref`, `dataset`, `next_ref`, `append` | `next_ref`에 다음 페이지 버튼을 주면 마지막 페이지까지 넘기며 전부 추출 |
| `download_table` | `ref`, `dataset`, `timeout_sec` | 화면의 엑셀·CSV 내려받기 버튼을 눌러 받은 파일을 데이터셋에 담는다 (4.2절) |
| `fill_table` | `ref`, `dataset`, `add_ref` | 입력 칸이 있는 표의 빈 행에 데이터셋을 통째로 채운다 (4.1절). `risk`가 R2 이상인 스킬만 가능 |
| `transform` | `source`, `target`, `steps` | `filter`, `group`, `sort`, `select`, `limit` |
| `write_excel` | `filename`, `sheets` | |
| `ask_user` | `question` | |
| `next_step` | | 검사 줄이 없는 단계에서만 |
| `finish` | `summary` | 마지막 단계에서만 |
| `abort` | `reason` | 중간에 그만둘 때 |

### 4.1 표 입력 (`fill_table`)

엑셀에서 복사해 웹 화면의 표에 붙여 넣던 작업을 대신합니다.

- 데이터셋의 **컬럼 이름이 표의 머리글과 같아야** 합니다. 표에 없는 컬럼이 있으면 아무것도 넣지 않습니다. 표에만 있는 컬럼(순번 등)은 건드리지 않습니다.
- **비어 있는 표에만** 입력합니다. 이미 값이 있으면 실패합니다.
- 빈 행이 모자라면 `add_ref`의 행 추가 버튼을 눌러 늘립니다.
- **쓰기 전에 전부 검사**합니다. 선택 상자에 없는 값, 숫자 칸에 숫자가 아닌 값이 하나라도 있으면 몇 행의 무슨 칸인지 알려주고 아무것도 쓰지 않습니다.
- 쓴 뒤에는 화면 값을 다시 읽어 원본과 대조합니다. 다르면 실패이고 다음 단계로 넘어가지 못합니다.
- 저장·상신 직전에 한 번 더 대조합니다. 그 사이에 화면 값이 바뀌었으면 누르지 않습니다.

### 4.2 파일 내려받기 (`download_table`)

화면에 엑셀·CSV 내려받기 버튼이 있으면 표를 페이지마다 넘기며 추출하는 것보다 이쪽이 빠르고, 화면에 다 보이지 않는 전용 그리드에서도 쓸 수 있습니다.

```
4. download_table로 "엑셀 다운로드" 버튼을 눌러 받은 파일을 데이터셋 `wip`에 담는다. args는 다음을 그대로 쓴다.
   `{"ref": "엑셀 다운로드", "dataset": "wip"}`
   - 검사: rows("wip") == page_number("총 ([\d,]+)건")
```

- 파일의 **첫 시트, 첫 행을 컬럼 이름**으로 읽습니다. xlsx와 csv(UTF-8, EUC-KR)를 읽고, 형식은 확장자가 아니라 내용으로 판별합니다.
- 받은 행 수를 화면의 총 건수와 맞춰 보는 검사를 함께 적으세요. 내려받기가 조회 조건을 따르지 않는 화면을 걸러냅니다.
- 파일의 주소가 스킬의 `domains` 밖이면 읽지 않습니다. 화면이 직접 만드는 파일(blob)은 그 화면의 주소로 봅니다.
- "엑셀 저장"처럼 내려받기를 뜻하는 이름은 누를 수 있지만, 그 밖의 저장·상신 계열 버튼("엑셀 등록" 등)은 이 도구로 누를 수 없습니다.
- `timeout_sec`(기본 30, 최대 120) 안에 내려받기가 시작되지 않으면 실패입니다. 서버가 파일을 만드는 데 오래 걸리는 화면이면 늘리세요.
- 파일은 사용자의 내려받기 폴더에도 평소처럼 저장됩니다. 확장은 PC의 파일을 읽을 수 없어, 서버가 주는 파일은 같은 주소를 사용자의 로그인 세션으로 한 번 더 받아 읽습니다.

읽지 못하는 경우

| 경우 | 대응 |
|---|---|
| 구형 엑셀(`.xls`), 엑셀 확장자를 단 웹 문서 | xlsx·csv 버튼을 쓰거나 `extract_table`로 추출 |
| 버튼을 누를 때마다 서버가 폼 전송(POST)으로 파일을 만드는 화면 | 같은 주소를 다시 받아도 그 파일이 오지 않아 실패함 → `extract_table`로 추출 |
| 파일이 다른 서버에서 내려옴 | 그 주소를 `dogent.config.ts`의 `sitePermissions`와 스킬의 `domains`에 추가 |
| 30MB를 넘는 파일 | 조회 조건을 좁힘 |

### 4.3 새 창과 알림·확인 창

**새 창.** 버튼이나 링크를 눌러 새 창(팝업)이나 새 탭이 열리면, 그 뒤의 단계는 새 창을 대상으로 합니다. 스킬에는 따로 적을 것이 없고, 새 창이 열렸는지는 `url("주소 일부")` 검사로 확인합니다. 새 창이 스스로 닫히면(값을 고르면 닫히는 찾기 창 등) 원래 창으로 돌아옵니다. 직접 닫아야 하면 `close_tab`을 씁니다. 처음 창은 닫지 않습니다.

```
2. click으로 "Lot 찾기" 버튼을 한 번 누른다. args는 다음을 그대로 쓴다.
   `{"ref": "Lot 찾기"}`
   - 검사: url("lot-popup.html") and text("홀드 Lot 찾기")
3. click으로 표에서 {lot} 행의 "선택" 버튼을 한 번 누른다. args는 다음을 그대로 쓴다.
   `{"ref": "선택", "row": "{lot}"}`
   - 검사: value("Lot ID") == "{lot}"
```

**알림·확인 창.** 브라우저의 알림(alert)·확인(confirm)·입력(prompt) 창은 실행 중에는 화면에 뜨지 않고, 에이전트가 내용을 받아 동작 결과에 적습니다.

| 창 | 처리 |
|---|---|
| 알림 | 넘어간다. 내용은 `dialog("글자")` 검사와 `dialog_text("정규식")` 기록으로 쓸 수 있다 |
| 확인 | **기본은 취소**이고 그 동작은 실패가 된다. 확인을 눌러야 하면 그 단계의 인자에 `"accept_dialog": true`를 적는다 |
| 저장·상신을 묻는 확인 | 사용자 승인을 받은 제출 단계(`submit_steps`)의 버튼에서만 확인을 누른다. `accept_dialog`로는 넘길 수 없다 |
| 입력 | 취소하고 실패가 된다 (답할 수 없음) |

```
5. click으로 "상신" 버튼을 한 번 누른다. args는 다음을 그대로 쓴다. 누르기 전에 사용자 승인을 받는다.
   `{"ref": "상신"}`
   - 검사: did("click") and dialog("접수되었습니다")
   - 기록: receipt = dialog_text("접수 번호: (\S+)")
```

지금 안 되는 것: 다른 사이트로 열리는 새 탭이 뜨자마자 띄우는 알림 창, 새 창을 여는 조작의 녹화.

### 4.4 표 안의 버튼·링크·입력란

표는 통째로 한 요소로 읽히지만, 칸 안의 버튼·링크·입력란은 표 바로 아래에 그 행의 글자와 함께 따로 나옵니다.

```
[4] table "홀드 Lot" rows=3 cols=[Lot ID, 제품, 공정, 홀드 사유, ]
[5] button "선택" row="P7-00012 | DR5-16G | PHOTO | 검사 대기 | 선택"
[6] button "선택" row="P7-00031 | NV2-512 | ETCH | 설비 점검 | 선택"
```

행마다 같은 이름의 요소가 있으면 `row`에 그 행에만 있는 글자를 적어 가립니다. 행의 글자에 `row`가 들어 있으면 그 행으로 봅니다.

```markdown
3. click으로 표에서 {lot} 행의 "선택" 버튼을 한 번 누른다. args는 다음을 그대로 쓴다.
   `{"ref": "선택", "row": "{lot}"}`
```

- `row`에 맞는 행이 없거나 여러 행이 맞으면 누르지 않고 오류로 알립니다. 다른 행을 대신 고르지 않습니다.
- 라벨이 없는 입력 칸은 열 머리글이 이름입니다. 예: `{"ref": "수량", "row": "P7-00031", "text": "25"}`
- 표 하나에서 따로 나오는 요소는 60개까지입니다. 여러 행에 값을 넣는 일은 `fill_table`을 씁니다.
- 머리글 없이 입력란이나 버튼을 담은 `<table>`은 화면 배치용으로 보고 표로 읽지 않습니다. 안의 요소는 보통 요소처럼 나옵니다.
- 녹화할 때 행마다 있는 버튼을 누르면 `row`가 그 행의 첫 칸 글자로 적힙니다. 행이 실행할 때마다 달라지면 `{입력값}`으로 바꾸세요.

### 4.5 성공한 경로 기억

인자를 적지 않은 단계는 모델이 화면을 보고 동작을 정합니다. 그 동작으로 단계가 끝나면 이 PC에 저장해 두고, 같은 스킬을 다시 실행할 때 모델을 부르지 않고 그대로 다시 합니다. 실행 기록에는 "기억한 경로"로 표시됩니다.

- 요소는 이름(과 표의 행)으로 저장합니다. 입력값과 똑같은 글자는 `{이름}`으로 저장해, 입력값이 달라지면 그 값이 들어갑니다.
- 입력값에서 나왔는지 알 수 없는 글자가 섞인 경로(예: 모델이 입력값을 고쳐 쓴 경우)는 입력값이 같을 때만 다시 씁니다.
- 다시 하는 동작도 정책 검사, 사용자 승인, 단계 검사를 똑같이 거칩니다. 저장·상신을 승인 없이 누르는 일은 없습니다.
- 저장한 동작이 지금 화면에서 통하지 않으면(요소가 없어짐, 동작 실패) 그 단계는 모델이 다시 맡고, 새로 찾은 경로로 바꿔 저장합니다.
- 단계를 넘길지(`next_step`), 끝맺는 말(`finish`), 질문은 저장하지 않습니다. 검사가 없는 단계는 넘길 때마다 모델을 한 번 부릅니다. 검사를 적어 두면 모델 없이 넘어갑니다.
- 스킬의 버전이나 본문이 바뀌면 예전 경로는 쓰지 않습니다. 설정에서 끄거나 지울 수 있습니다.

## 5. 저장·상신 (R3)

버튼 이름에 저장, 상신, 제출, 삭제, 승인, 결재, 등록, 확정, 반려 등이 들어 있으면 R3 동작으로 봅니다. 이 판정은 모델이 아니라 이름 규칙으로 합니다.

R3 버튼을 누르려면 다음을 모두 통과해야 합니다.

1. 스킬의 `risk`가 `R3`다.
2. 지금 단계가 `submit_steps`에 있다. 단계는 순서대로만 진행되므로, 앞 단계의 검사가 모두 통과한 뒤에만 도달한다.
3. `submit_labels`가 있으면 버튼 이름이 그 안에 있다.
4. **제출 전 대조**: 앞 단계들의 `value(...)` 검사를 현재 화면으로 다시 평가하고, `fill_table`로 채운 표를 다시 읽어 원본과 비교한다. 확인이 끝난 값이 그 뒤에 바뀌었으면 누르지 않는다.
5. **사용자 승인**: 화면에서 다시 읽은 입력 값과 채운 표(행 수, 처음 10행)를 보여주고 승인을 받는다. 승인하지 않으면 실행을 끝낸다.
6. 한 단계에서 한 번만 누른다.

**시험 실행**을 켜면 5번에서 승인을 묻지 않고 멈춥니다. 화면의 입력은 그대로 남아 사람이 확인할 수 있습니다.

## 6. policy.yaml — 입력값 규칙

실행을 시작하기 전에 적용합니다. 위반이 있으면 화면에 접속하지 않습니다.

```yaml
rules:
  - field: src_ip
    deny_cidr_wider_than: 24   # /24보다 넓은 대역 금지
    deny_values: ["0.0.0.0"]
  - field: period_days
    min: 1
    max: 365
  - field: reason
    min_length: 10
```

| 규칙 | 뜻 |
|---|---|
| `deny_cidr_wider_than: n` | 접두 길이가 n보다 짧은 CIDR 금지 |
| `deny_values` | 금지 값 (대소문자 무시) |
| `min`, `max` | 숫자 범위 |
| `min_length` | 최소 글자 수 |

`field`는 스킬의 입력 이름이어야 합니다. 규칙 값은 스킬 오너와 보안 부서가 정합니다.
