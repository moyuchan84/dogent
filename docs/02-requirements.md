## 3. 보안 요구사항

| ID | 요구사항 |
|---|---|
| SEC-01 | 모델 호출은 사내 Gemma API로만 한다. 외부 네트워크로 데이터를 보내지 않는다 |
| SEC-02 | 에이전트는 사용자 본인의 로그인 세션과 권한 안에서만 동작한다. 별도 서비스 계정이나 권한 상승을 쓰지 않는다 |
| SEC-03 | 계정·비밀번호·인증서를 저장하거나 입력하지 않는다 |
| SEC-04 | 웹 페이지와 파일의 내용은 데이터로만 취급하고 지시로 해석하지 않는다 |
| SEC-05 | 기존 시스템의 결재·승인 절차를 우회하지 않는다 |
| SEC-06 | 감사 로그는 사용자가 임의로 수정할 수 없게 보관한다 (Phase 3에서 중앙 수집) |
| SEC-07 | 확장·클라이언트는 사내 인증서로 서명해 배포한다 |
| SEC-08 | 배포 스킬은 검토 승인을 거친 것만 실행된다 |
| SEC-09 | 모델에 전달되는 화면 스냅샷에서 민감 필드(비밀번호 입력란 등)는 제외한다 |
| SEC-10 | 로그에 남는 데이터 범위(화면 값 포함 여부)를 보안 부서와 합의해 정한다 |

## 4. 제약 및 가정

- 사내 Gemma API가 툴 호출(또는 JSON 출력 강제)을 지원한다고 가정한다. 이미지 입력은 있으면 좋지만 필수는 아니다.
- 크롬 확장 설치와 `debugger` 권한 사용이 보안 정책상 허용된다고 가정한다. 불가하면 content script만으로 동작하는 축소안으로 간다.
- 대상 시스템은 Chrome/Edge에서 동작하는 웹 시스템이다. IE 전용, ActiveX, 설치형 프로그램은 범위 밖이다.
- 위 세 가지는 Phase 0에서 확인하며, 결과에 따라 요구사항을 조정한다.

## 5. 범위 밖

- 무인 서버에서 도는 완전 자동화 (사용자 PC와 세션이 전제)
- 사용자 권한을 넘는 작업
- 결재·승인 행위의 대행
- 웹이 아닌 데스크탑 애플리케이션 제어
