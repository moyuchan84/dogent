DOGENT · 크롬 확장 + 클라이언트 + 데스크탑 앱

받아서 실행하고, 내 업무 시나리오까지 만들어 보기

Dogent는 두 가지로 씁니다. 브라우저 오른쪽 사이드 패널에서 시키거나(A~E), PC의 터미널 클라이언트(F)나 데스크탑 앱(G)에서 시킵니다. 어느 쪽이든 화면을 읽고 누르는 일은 크롬 확장이 하고, 스킬과 안전장치는 같습니다. 먼저 모의 사이트와 모의 모델로 흐름을 익힌 뒤, 사내 Gemma와 실제 업무 화면에 연결합니다. 아래 화면과 터미널 출력은 모두 이 저장소를 빌드해 실제로 돌리면서 캡처한 것입니다.

① 준비설치 · 빌드 · 확장 로드 (10분)
② 사이드 패널A~E 시나리오 따라하기 (20분)
③ 클라이언트·앱F 터미널 · G 데스크탑 앱 (15분)
④ 사내 연결.env.company.local 하나로 둘 다 빌드
⑤ 내 시나리오녹화나 말로 시켜 스킬 만들기

1. 설치와 빌드 사내 PC에서 한 번

필요한 것: Node.js 20 이상, pnpm, Chrome. 소스는 git clone으로 받거나, GitHub에 접근할 수 없으면 zip으로 옮깁니다. zip으로 옮길 때 node_modules, .output, test-results는 빼세요.

1소스 받기와 설치

git clone https://github.com/moyuchan84/dogent.git
cd dogent
pnpm install
pnpm build          # .output/chrome-mv3 에 확장이 만들어짐
pnpm client:build   # client/dist/dogent.mjs 에 터미널 클라이언트 (F에서 씀)
사내망에서 pnpm install이 막히면 사내 npm 미러로 바꿉니다: pnpm config set registry <사내 미러 주소>

2제대로 받았는지 확인

pnpm typecheck
pnpm test           # 235개 통과면 정상 (약 1분)

브라우저 자동 테스트(pnpm e2e)는 Chromium을 내려받아야 해서 사내망에서는 안 될 수 있습니다. 건너뛰어도 됩니다.

2. 크롬에 확장 올리기

1확장 프로그램 화면 열기

  1. 주소창에 chrome://extensions
  2. 오른쪽 위 개발자 모드 켜기
  3. 압축해제된 확장 프로그램 로드 → 저장소의 .output/chrome-mv3 폴더 선택 (집·회사 설정으로 빌드했으면 -home·-company가 붙은 폴더)
  4. 툴바의 퍼즐 아이콘에서 Dogent를 고정해 두면 편합니다
개발자 모드가 회색으로 막혀 있으면 회사 Chrome 정책입니다. IT에 확장 로드 예외를 요청해야 합니다.

코드를 고쳐 다시 빌드했으면 이 화면에서 Dogent 카드의 ⟳(새로고침)를 누릅니다.

2모의 사이트와 모의 모델 띄우기

터미널 두 개를 엽니다. 둘 다 켜 둔 채로 다음 단계를 진행합니다.

# 터미널 1: 모의 업무 사이트
pnpm mock:site      # http://localhost:4173

# 터미널 2: 모의 모델 API
pnpm mock:llm       # http://localhost:4174/v1

모의 사이트에는 연습용 화면이 있습니다.

주소화면
/wip.html재공 현황 조회 (페이지 넘김, 엑셀 다운로드)
/portal.html같은 화면을 iframe 안에 넣은 포털
/fw.htmlIP 방화벽 해제 신청서
/adjust.html재공 수량 조정 입력 표
/adjust-grid.html입력 칸 없는 붙여넣기 전용 그리드
모의 모델은 스킬에 적힌 절차를 규칙대로 따라가는 스크립트입니다. 흐름이 도는지 확인하는 용도이고, 모델의 판단력은 사내 Gemma를 연결해야 볼 수 있습니다.

A. 재공 확인 R1 조회 말로 시키면 엑셀까지

조회만 하는 업무입니다. 요청 한 줄을 스킬과 입력값으로 해석하고, 페이지를 넘기며 표를 읽어 엑셀 세 시트로 정리합니다.

1사이드 패널 열기

wip.html 탭에서 툴바의 Dogent 아이콘을 누르면 오른쪽에 패널이 열립니다. 패널은 지금 보고 있는 탭을 조작합니다.

위쪽 막대에 화면 점검과 설정이 있고, 그 아래 탭이 세 개입니다. 실행, 스킬 만들기, 기록. 설정과 화면 점검은 실행 화면 자리에 따로 열리고, ← 돌아가기(또는 Esc)로 닫으면 적던 요청과 진행 중인 실행이 그대로 남아 있습니다.

2요청을 적고 해석

"무엇을 할까요?" 칸에 7라인 재공 확인해줘를 적고 해석을 누릅니다. 모델이 스킬(재공 확인)을 고르고 라인 칸에 7라인을 채웁니다.

해석 결과가 틀리면 스킬과 입력값을 손으로 고쳐도 됩니다. 해석 없이 스킬을 직접 골라 칸을 채워도 됩니다.

3실행 — 업무 화면에서 일어나는 일

업무 화면 둘레에 파란 테두리가 생기고, 오른쪽 아래에 Dogent가 조작 중이 뜹니다. 클릭·입력·선택 직전에는 대상 요소에 포인터와 라벨이 표시됩니다.

조작 중에는 그 탭을 건드리지 마세요. 멈추려면 패널의 중지를 누릅니다.

4진행 기록과 결과 파일

패널의 진행에 단계마다 무엇을 했고 확인됐는지 쌓입니다. 모델 호출 없음은 스킬에 도구와 인자가 적혀 있어 모델 없이 바로 실행한 단계입니다.

끝나면 초록 상자에 요약이 나오고, 재공확인_7라인.xlsx가 내려받기 폴더에 저장됩니다. 시트는 원본 / 정체Lot / 공정별집계 세 개입니다.

패널 아래의 wip · 128행 같은 줄을 펼치면 엑셀을 열지 않고도 데이터를 볼 수 있습니다.

B. 방화벽 신청 R3 상신 사람이 승인해야 제출

저장·상신 버튼을 누르는 업무는 스킬에 선언된 단계와 버튼에서만, 사용자가 승인한 뒤에만 누릅니다. 사내에서 쓰기 업무를 시험할 때 가장 먼저 익혀 둘 부분입니다.

1스킬을 고르고 입력값 채우기

http://localhost:4173/fw.html을 열고 패널의 스킬에서 IP 방화벽 해제 신청 (R3)을 고릅니다. 입력 칸이 스킬에 맞게 바뀝니다.

예시 값: 출발지 10.10.1.15, 목적지 10.20.3.7, 포트 1521, 기간 90.

출발지에 10.10.0.0/16처럼 넓은 대역을 넣으면 실행 전에 거부됩니다. 스킬 폴더의 policy.yaml 규칙입니다.

2실행하면 상신 직전에 승인 요청

입력을 마치고 "상신"을 누르기 전에 패널에 빨간 승인 상자가 뜹니다. 표시되는 값은 화면에서 다시 읽은 현재 값입니다. 입력한 값과 같은지 보고 결정합니다.

  • 승인하고 상신 → 실제로 제출되고 신청 번호(FW-000001)가 결과에 남음
  • 취소 → 제출하지 않고 멈춤. 화면의 입력값은 그대로 남음

3시험 실행: 상신 직전에 멈추기

입력 칸 아래 시험 실행을 켜고 실행하면, 입력까지만 하고 상신 버튼 앞에서 멈춥니다. 승인 상자도 뜨지 않고 아무것도 제출되지 않습니다.

사내 실제 시스템에서 R3 스킬은 반드시 시험 실행부터 돌려 보세요.

C. 스킬 만들기 녹화하거나, 말로 시켜 잘 된 일을 저장

업무를 한 번 해 보이면 SKILL.md 초안이 나옵니다. 형식을 외울 필요가 없습니다. 사내에서 새 시나리오를 만들 때 이 순서를 그대로 씁니다. 자세한 기준은 docs/06-skill-authoring.md.

1업무 첫 화면에서 스킬 만들기 탭

업무를 시작하는 화면을 먼저 엽니다. 로그인은 미리 해 둡니다(로그인 화면에서는 녹화가 시작되지 않고, 비밀번호 칸은 녹화하지 않습니다).

칸예
스킬 IDfw-recorded (영문 소문자와 -)
이름방화벽 신청 녹화
설명무엇을 하는 업무인지 한 문장
담당 부서화면이 바뀌면 고칠 책임이 있는 부서

채우고 녹화 시작.

2평소대로 업무를 한 번 하기

업무 화면에서 그냥 평소처럼 입력하고 누릅니다. 패널에 조작이 순서대로 쌓입니다.

  • 실행할 때마다 입력받기(기본 켜짐): 그 값이 스킬의 입력 칸이 됩니다. 예: IP, 사유
  • 끄면 녹화한 값을 고정해서 씁니다. 예: 늘 같은 프로토콜
  • 잘못 누른 것은 빼기
  • 표를 엑셀로 받아야 하면 화면의 표 읽기 추가, 엑셀 내용을 입력 표에 넣어야 하면 엑셀로 표 채우기 추가
  • 입력 이름·설명, 목적, 말로 적은 단계, 화면 정리도 넣을 수 있습니다 (아래 6)

다 했으면 녹화 끝.

녹화 중에 누른 저장·상신은 실제로 제출됩니다. 실제 시스템이라면 제출해도 되는 값으로 녹화하거나, 상신 직전에서 녹화를 끝내고 저장 단계는 초안에 손으로 더하세요.

3품질 검사 확인하고 초안으로 저장

녹화가 끝나면 초안 SKILL.md와 품질 등급(A~F)이 나옵니다. B 이상이어야 배포 기준입니다. 지적 사항(예: W07 입력값 규칙 없음)을 보고 아래 편집 칸에서 직접 고치면 바로 다시 검사합니다.

상신 버튼을 눌렀다면 risk: R3, submit_steps, submit_labels가 자동으로 선언됩니다.

모델로 다듬기를 누르면 설명·입력 이름·단계 설명 문장을 모델이 다듬어 줍니다(동작이 바뀌는 제안은 버림). 끝나면 초안으로 저장.

4다른 값으로 시험 실행

업무 첫 화면을 다시 열고 실행 탭에서 방금 저장한 초안을 고릅니다. 녹화 때와 다른 값을 넣고, R3라면 시험 실행을 켠 채 실행합니다.

입력 칸 이름이 v1, v2…로 붙어 있어도 화면에는 라벨(출발지 IP 등)이 보입니다.

5SKILL.md 내려받아 스킬로 넣기

스킬 만들기 탭의 내 초안에 세 가지가 모두 체크되면 SKILL.md 내려받기가 됩니다.

# 내려받은 파일을 스킬 폴더에 넣고 다시 빌드
skills/fw-recorded/SKILL.md
pnpm skill:lint     # 번들 스킬 검사
pnpm build          # 그다음 chrome://extensions 에서 새로고침

다시 빌드하지 않고 나눠 쓰려면 공유 스킬 저장소(WXT_SKILLS_URL)를 씁니다(README "다시 빌드하지 않고 스킬 공유하기").

손으로 쓰고 싶으면 pnpm skill:new my-skill "스킬 이름"으로 틀을 만듭니다. 형식은 docs/05-skill-spec.md.

6녹화 중에 끼워 넣기: 이름, 목적, 말로 단계, 화면 정리

클릭만 따라 하는 스킬은 화면이나 값이 조금만 달라도 깨집니다. 녹화하면서 아래를 넣어 두면 요청에 맞춰 값이 바뀌고, 모델이 상황에 맞춰 수행합니다.

넣는 것하는 법실행할 때
매개변수 이름·설명"실행할 때마다 입력받기" 아래 칸에 영문 이름(keyword)과 설명"NV2 검색해서 정리해줘" 같은 요청에서 설명을 보고 값을 뽑음
목적조작 옆 목적 → 한 줄 (예: 검색 결과를 띄운다)녹화한 클릭이 실패하면 이 문장으로 같은 일을 하는 요소를 찾음
말로 단계 추가할 일을 문장으로 (예: HOLD인 Lot이 있으면 열어 사유를 확인한다)모델이 화면을 보고 수행. 맨 마지막이면 결과를 정리해 보고하며 끝냄
화면 정리 추가화면의 글 또는 표를 고르고 정리 기준을 적음. 여러 페이지면 끝까지 읽을지 선택정리한 글이 결과 보고에 붙음. 자료(글 12,000자, 표 200행까지)를 사내 모델에 보냄

정리 기준에 {keyword}처럼 입력 이름을 쓰면 실행할 때 그 값이 들어갑니다.

7말로 시켜 잘 된 일을 스킬로

녹화하지 않아도 됩니다. 실행 탭에서 자유 요청으로 시켜 끝까지 잘 되면 결과 아래 이 실행을 스킬로 저장이 나옵니다.

  • 성공한 동작만 단계로 옮기고, 헤매다 실패한 동작은 버립니다
  • 요청에 나온 값(8라인)은 실행할 때마다 받는 값으로 제안하고, 라벨을 보고 이름을 붙입니다(라인 → line)
  • 요청 문장은 마지막 말로 적은 단계가 되어, 다른 라인으로 실행하면 그 라인의 결과로 답합니다

녹화 목록처럼 이름·설명·목적을 고치고 스킬 ID와 담당 부서를 적은 뒤 초안 만들기 → 품질 검사 → 초안으로 저장. 터미널 클라이언트에서도 같은 일을 묻고 답하며 합니다(F-6).

D. 엑셀로 묶어 실행 행마다 같은 스킬을 한 번씩

신청 여러 건을 엑셀 한 장으로 처리합니다. 컬럼은 입력 이름이나 라벨(출발지 IP 등)로 자동 연결되고, 입력값 검사와 정책은 실행 전에 행마다 적용됩니다.

1엑셀 준비하고 고르기

첫 행에 라벨을 적은 엑셀을 만듭니다.

출발지 IP목적지 IP포트비고
10.10.1.1510.20.3.71521첫 번째
10.0.0.0/810.20.3.71521정책에 걸림
10.10.1.1610.20.3.8443두 번째

끝나면 결과 엑셀 내려받기로 행별 결과(신청 번호 포함)를 받습니다.

F. 터미널 클라이언트 사이드 패널 대신 PC 프로그램으로 시키기

1빌드

확장과 같은 저장소에서, 같은 환경 파일로 빌드합니다. 결과는 Node만 있으면 도는 파일 하나(client/dist/dogent.mjs)입니다.

pnpm client:build              # 모의 모델 (localhost:4174)
pnpm client:build:home         # .env.home.local (Ollama)
pnpm client:build:company      # .env.company.local (사내 Gemma)

pnpm client help               # 명령 목록

이 문서의 pnpm client …는 node client/dist/dogent.mjs …와 같습니다. 다른 PC에 옮길 때는 이 파일 하나만 복사해도 됩니다.

회사 설정으로 빌드한 dogent.mjs에는 API 키가 들어갑니다. 저장소에는 올라가지 않게 되어 있습니다(.gitignore). 메일·메신저로 옮기지 마세요.

5저장·상신은 브라우저의 승인 창에서

R3 스킬이 상신 버튼에 다다르면 터미널에 무엇을 승인하는지 나오고, 브라우저에 Dogent 승인 창이 뜹니다. 값은 화면에서 다시 읽은 것입니다. 창에서 승인하고 상신을 눌러야 제출되고, 취소하거나 창을 닫으면 제출하지 않고 멈춥니다.

승인은 확장이 받습니다. 그래서 클라이언트든 Claude Code든 어떤 프로그램이 붙어도 사람이 승인하지 않은 상신은 일어나지 않습니다. 시험 실행은 --dry-run입니다.

크롬과 엣지 둘 다에 확장을 올려 연결을 켜 두면 둘 다 붙습니다. 어느 브라우저를 조작할지 고릅니다. 같은 종류 브라우저가 둘이면(크롬 프로필 둘 등) 확장의 클라이언트 연결 → 이 브라우저 이름에 구분할 이름을 붙입니다(예: 업무용 크롬).

$ pnpm client browsers

  [1] (사용 중) Microsoft Edge 141 — WebSocket
  [2] 업무용 크롬 — WebSocket

pnpm client tabs --browser 크롬               # 이번만 크롬
pnpm client config browser edge              # 늘 엣지
  • 고르지 않으면 지금 붙어 있는 브라우저를 쓰고, 실행 중에 다른 브라우저가 붙어도 바뀌지 않습니다.
  • 번호는 실행할 때마다 다시 매겨지므로, 명령에는 이름을 씁니다. 대화 모드에서는 browser 2처럼 번호도 됩니다.
  • 데스크탑 앱은 위쪽 목록에서 고릅니다(G). Claude Code에서는 browsers_list, browser_select 도구가 같은 일을 합니다.

G. 데스크탑 앱 터미널 없이 창에서 시키기 (Electron)

F의 클라이언트에 화면을 입힌 앱입니다. 엔진이 같아서 스킬, 설정, 실행 기록(%USERPROFILE%\.dogent)을 함께 씁니다. 현업 사용자에게는 이 앱 하나와 브라우저 확장만 나눠 주면 됩니다.

1빌드와 실행

pnpm desktop                   # 빌드하고 바로 띄우기 (모의 모델)
pnpm desktop:pack              # 한 파일 실행본 desktop/release/Dogent-0.1.0.exe (약 96MB)
pnpm desktop:pack:company      # 회사 설정(.env.company.local)으로 실행본
  • 실행본은 설치 없이 더블클릭으로 뜹니다. pnpm office:build로 오피스 도구를 먼저 만들어 두면 실행본 안에 함께 들어갑니다.
  • 사내망에서 Electron을 내려받지 못하면 pnpm install 전에 set ELECTRON_MIRROR=(사내 미러)/electron/
  • 터미널 클라이언트와 앱을 동시에 켜면 브리지 포트가 겹칩니다. 하나만 켭니다.
회사 설정으로 만든 실행본에는 API 키가 들어갑니다. 사내에서만 나누고, 저장소·메일·메신저로 옮기지 마세요 (desktop/dist, desktop/release는 저장소에 올라가지 않음).

  3. 앱 위쪽에 브라우저 이름이 보이고 초록 점이 켜지면 연결된 것입니다

  • 실행은 카드 하나로 보입니다. 단계마다 무엇을 했는지, 끝나면 결과와 저장한 파일(폴더에서 보기)
  • 실행 중에는 중지. 아래 체크로 자유 요청의 저장·상신 허용, 시험 실행(상신 직전에 멈춤)

4저장·상신은 브라우저의 승인 창에서

R3 스킬이 상신 버튼에 다다르면 앱의 실행 카드에 빨간 안내와 화면에서 다시 읽은 값이 나오고, 브라우저에 Dogent 승인 창이 뜹니다(F-5와 같은 창). 승인은 그 창에서만 합니다.

5잘 된 자유 요청을 내 스킬로

맞는 스킬이 없는 요청은 지금 화면에서 자유 요청으로 합니다. 끝나면 스킬로 저장할까요? 카드가 나오고, 매개변수 이름·설명, 스킬 ID, 담당 부서를 카드에 차례로 답합니다(F-6과 같은 질문). 저장하면 왼쪽 개인에 바로 나타납니다.

API 제공 측에서 받은 값 세 개와 사용자 유형을 채웁니다. 업무 시스템 주소는 나중에 패널에서 더하면 되므로 비워 둬도 됩니다.

WXT_LLM_BASE_URL=(api_base_url)      # /chat/completions 앞까지
WXT_LLM_API_KEY=(credential_key)     # 헤더 틀의 {key}
WXT_LLM_MODEL=(model)
WXT_LLM_USER_TYPE=(user_type)        # 헤더 틀의 {userType}
WXT_SITE_PERMISSIONS=                # 비워 둬도 됨. 패널에서 더함

요청 헤더 틀은 예시 파일에 이미 들어 있어 고칠 것이 없습니다. 필수 헤더인 Send-System-Name은 WXT_LLM_SYSTEM_NAME(기본 RFGo)으로 채워지고, 틀이 없거나 틀에서 빠져도 늘 붙습니다.

WXT_LLM_SYSTEM_NAME=RFGo
WXT_LLM_HEADERS='{"x-dep-ticket":"{key}","Send-System-Name":"{systemName}",
  "user-id":"{userId}","user-type":"{userType}",
  "prompt-msg-id":"{uuid}","completion-msg-id":"{uuid}",
  "accept":"application/json","content-type":"application/json"}'
# 실제 파일에서는 한 줄로 적습니다
자리표시자들어가는 값
{key}WXT_LLM_API_KEY (credential_key)
{userId}사용자 ID(사내 SSO ID). 사람마다 달라서 패널 설정에서 각자 입력
{userType}WXT_LLM_USER_TYPE
{systemName}WXT_LLM_SYSTEM_NAME (기본 RFGo). 설정 화면의 "시스템 이름"에서도 바꿀 수 있음
{uuid}요청마다 새로 만든 UUID (메시지 ID)

헤더 틀이 있으면 Authorization: Bearer는 보내지 않습니다. 틀의 형식이 틀리면 빌드가 멈추고 어디가 틀렸는지 알려 줍니다.

.env.company.local과 빌드 결과물에는 키가 그대로 들어갑니다. Git·메일·메신저로 옮기지 말고, 회사 PC에서 직접 만드세요.

7사내 화면에서 화면 점검

실제 업무 화면을 열고(로그인까지 마친 상태) 패널 위쪽의 화면 점검을 누릅니다. 화면을 바꾸지 않고 읽기만 해서, 녹화하기 전에 막히는 곳을 알려 줍니다.

표시뜻
막힘조작할 사이트 목록에 없는 화면, 읽지 못한 iframe, 로그인 화면. 목록에 없으면 이 사이트 허용을 누르고 크롬이 묻는 창에서 허용 (다시 빌드할 필요 없음)
확인그림(canvas)으로 그린 그리드, 웹 컴포넌트 안 요소, 머리글 없는 표, 이름 없는 요소. 되긴 하지만 해당 부분은 시험 실행으로 꼭 확인
정상읽은 표(행·열 수, 입력 칸 여부)와 요소 수

보고서 내려받기로 받은 .md 파일은 입력값과 표의 값을 넣지 않습니다. 기본으로 라벨·머리글·버튼 이름은 글자 수만, 호스트는 "호스트 A"로 가립니다. 화면이 이상하게 읽히면 이 보고서를 개발 담당에게 보내 주세요.

4. 첫 사내 시나리오 고르기

사내 화면 구조(iframe, 그리드 종류, 페이지 넘김 방식)가 가장 큰 미지수입니다. 위험이 낮은 것부터 하나씩 넓힙니다.

순서시나리오방법여기서 드러나는 것
0화면 점검패널 위쪽 화면 점검 (화면을 바꾸지 않음)허용 목록, iframe, 그림 그리드, 머리글 없는 표
1조회 → 엑셀 R1녹화 + 화면의 표 읽기 추가 (또는 화면의 엑셀 다운로드 버튼 누르기). 자유 요청으로 시켜 잘 되면 이 실행을 스킬로 저장도 됨화면·표가 읽히는지, 페이지 넘김이 되는지
2엑셀 → 입력 표 (저장 안 함)녹화 + 엑셀로 표 채우기 추가, 저장 단계 없이사내 그리드가 입력 칸형인지 붙여넣기형인지
3신청·저장 R3녹화 후 시험 실행으로만 반복 확인 → 마지막에 한 번 실제 승인승인 상자의 값 대조, 확인 창 처리
4여러 건 묶어 실행3번 스킬 + 엑셀행마다 첫 화면으로 돌아가는지

녹화 전에 확인할 것

  • 대상 시스템 주소가 설정 → 조작할 사이트에 있다 (없으면 화면 점검의 이 사이트 허용. 다시 빌드할 필요 없음)
  • 로그인을 미리 해 두었다 (로그인 화면이 보이면 에이전트가 멈춤)
  • 그 화면에서 화면 점검을 돌려 막힘이 없다
  • 업무의 첫 화면을 열어 둔 상태에서 녹화를 시작한다
  • 저장·상신 버튼은 녹화 중에 실제로 눌린다는 것을 알고 있다
  • 새 창(팝업)이 뜨면 1초쯤 기다린 뒤 조작한다
사내 스킬을 어디에 둘지: 사내에서 만든 SKILL.md에는 사내 시스템 주소와 화면 문구가 들어갑니다. 개인 GitHub 저장소에 올리지 말고, 사내 GitHub Enterprise의 팀 스킬 저장소(틀: templates/dogent-skills)에 PR로 올립니다. 확장은 그 목록 주소로, 클라이언트는 받아 둔 폴더(config teamSkills)로 읽습니다.
