# 29. PC 파일 도구와 첨부 (끌어다 놓기)

> 문서 상태: v0.1 (2026-11-16) · 구현됨. 사내 PC에서는 아직 확인하지 않음
> 관련: [17-claude-parity.md](17-claude-parity.md) (P1-3 끌어다 놓기), [28-tool-eval-and-constrained-decoding.md](28-tool-eval-and-constrained-decoding.md) (평가 세트), [27-gaps-and-improvements.md](27-gaps-and-improvements.md)

지금까지 에이전트는 PC 파일을 엑셀 COM(오피스 도구)이나 스킬의 파일 입력으로만 다뤘다. 그 밖의 파일 일은 Claude Code·opencode에 맡겨야 했다. 이번에 사내 Gemma만으로 **로컬 파일 → 웹 입력**과 **웹 → 로컬 파일**을 하도록 파일 도구 세 개와 첨부를 더했다.

## 1. 도구

| 도구 | 하는 일 | 어디서 |
|---|---|---|
| `list_files {"dir", "pattern"}` | 폴더의 파일 목록. 폴더 먼저, 파일은 최근에 고친 것부터 100개. dir가 없으면 읽을 수 있는 폴더와 첨부한 파일을 보인다 | 앱·터미널 |
| `read_file {"path", "dataset", "sheet", "table", "name"}` | 파일을 읽는다. 글은 결과로 보이고(6000자), `name`을 주면 글 전체를 `{out.name}`에 남긴다. 표는 `dataset`을 주어 데이터셋에 담는다 | 앱·터미널 |
| `write_file {"filename", "content", "dataset"}` | **결과 폴더에만** 글 파일을 쓴다. `content`는 `{out.}`·`{table.}`·`{rows.}`를 쓸 수 있고, `dataset`은 형식에 맞게 쓴다(csv·tsv는 BOM 포함, json은 객체 배열, md·txt는 표) | 앱·터미널·확장(내려받기) |

읽는 형식은 다음과 같다.

| 형식 | 읽는 것 |
|---|---|
| txt, md, log, json, xml, yaml, ini, sql 등 | 글. UTF-8로 안 읽히면 EUC-KR(CP949)로 읽는다 |
| csv, tsv | 표 1개. 머리글이 비거나 겹치면 `열2`, `이름_2`처럼 이름을 붙인다 |
| xlsx, xlsm | 시트 하나의 표 (`sheet`로 고름. 결과에 시트 이름들이 나온다) |
| docx | 문단 글과 문서 안의 표들 (표는 글에도 `\| 칸 \| 칸 \|`으로 들어간다) |
| pptx | 슬라이드 순서대로 글(`## 슬라이드 n`)과 표 |
| pdf | 쪽마다 글 (`## n쪽`). 스캔한 그림뿐인 PDF·암호 걸린 PDF는 읽지 못한다고 알린다 (글자 인식은 하지 않음). `unpdf`(pdf.js)를 PDF를 읽을 때만 불러온다 |
| html | 스크립트·태그를 뺀 글 |

읽지 않는 것: 예전 형식(xls·doc·ppt), 그림, 실행 파일, 30MB를 넘는 파일. 문서 보안(DRM)이 걸린 오피스 파일은 ZIP이 아니어서 바로 알아채고, 오피스 도구가 있으면 `excel_read`·`word_read`·`ppt_read`로 읽으라고 모델에 알린다. docx·pptx는 새 의존성 없이 Node 내장 zlib로 푼다(`client/src/files.ts`).

## 2. 무엇을 읽을 수 있나

- **읽을 수 있는 폴더**: 설정 `uploadDirs`(기본: 결과 폴더, 내려받기, 문서, 바탕 화면). 파일 올리기와 같은 설정이다. `dogent config uploadDirs "D:\업무;C:\Users\나\Downloads"`
- **첨부한 파일**: 어느 폴더에 있든 **그 파일만** 읽고 올릴 수 있다. 이름만 써도 찾는다.
- **첨부한 폴더**: 그 폴더 안을 읽을 수 있다.
- 숨김 폴더(`.`으로 시작), `.ssh` 같은 폴더, 키·접속 정보 파일(`id_rsa`, `*.pem` 등)은 읽지도 첨부하지도 않는다. 링크로 폴더 밖을 가리키면 실제 경로로 막는다 (파일 올리기와 같은 검사).
- 쓰기는 결과 폴더(`outputDir`)에만 하고, 실행 파일·스크립트 형식은 쓰지 않는다 (`txt md csv tsv json xml log`만).
- 파일에서 읽은 글은 `<file>`로 감싸 모델에 주고, 그 안의 지시는 따르지 않게 한다.
- 첨부는 대화가 끝날 때까지 남고, **새 대화**(`new`, `/clear`)에서 지운다.

## 3. 첨부하는 방법

| 어디서 | 방법 |
|---|---|
| 데스크탑 앱 | 창 어디에나 파일·폴더를 **끌어다 놓기**, 또는 입력 칸의 **클립 버튼**. 보내기 전까지 칩으로 보이고 ×로 뺀다. 보낸 요청에는 첨부한 파일 이름이 붙는다 |
| 터미널 | `dogent "요청" --file <경로> [--file <경로> …]` (`-f`) |
| 대화 중 | `첨부 <전체 경로>` · `첨부`(목록) · `첨부 지우기` |

첨부한 것은 다음에 쓰인다.

- **파일 도구**: 자유 요청이 첨부한 파일을 `read_file`로 읽는다.
- **파일 올리기**: `upload_file`이 첨부한 파일을 웹 화면의 첨부 칸에 올릴 수 있다 (올릴 수 있는 폴더 밖이어도. 승인 창은 그대로).
- **스킬 입력**: 파일 입력이 있는 스킬을 고를 때 입력이 비어 있고 첨부한 엑셀·CSV가 하나뿐이면 그 파일을 쓴다. 요청 해석에도 "(첨부한 파일: …)"을 함께 보낸다.

## 4. 요청이 어디로 가나

자유 요청에서 파일 도구는 **첨부가 있거나 요청에 경로·확장자·"파일"·"폴더"·"첨부" 같은 말이 있을 때** 붙인다 (`fileIntent`). 그래야 파일과 관계없는 요청의 도구 목록이 길어지지 않는다.

| 요청 | 통로 |
|---|---|
| 화면 일이 없고 파일만 (예: "첨부한 회의록 요약해서 md로 저장") | **파일만** (브라우저 연결을 기다리지 않음) |
| 화면 일과 파일 (예: "이 엑셀을 조정 화면에 입력해줘" + 첨부) | 브라우저 + 파일 |
| 엑셀·워드인데 오피스 도구가 없음 | 예전에는 그만뒀지만, 이제 파일을 직접 읽는다 (문서 보안이 걸린 파일은 못 읽음) |
| 엑셀·워드이고 오피스 도구가 있음 | 오피스 도구 (+ 파일 도구) |

스킬도 단계에 `read_file`·`list_files`를 쓰면 파일 통로가 붙는다 (`skillUsesFiles`). 확장 패널 단독 실행은 PC 파일을 읽을 수 없어서 `write_file`만 쓴다(내려받기로 저장).

## 5. 평가

평가 세트에 파일 도구 케이스 5개(`evals/tool-calls/files.json`)를 더했다: 첨부한 CSV 읽기, 읽은 표를 CSV로 쓰기, 다 했으면 끝내기, 경로를 모르면 목록부터 보기, 목록에서 찾은 파일을 전체 경로로 읽기. `dogent eval tools --tag files`로 따로 잰다. 다시 만들려면 `EVAL_SEED=1 pnpm vitest run tests/tool-eval-seed.test.ts`.

## 6. 남은 것

- **PDF 의존성**: `unpdf@2.1.0`을 더했다 (클라이언트·앱 한 파일이 3.8MB → 7.8MB). 사내 빌드 PC의 npm 미러에서 받을 수 있는지 확인한다. 스캔 PDF의 글자 인식(OCR)은 하지 않는다.
- 앱의 "새 요청" 버튼은 화면만 비우고 세션의 대화·첨부는 남는다. 첨부를 지우려면 "새 대화"를 입력한다.
- 확장 사이드 패널에는 끌어다 놓기가 없다 (확장은 PC 경로를 알 수 없음). 스킬의 파일 입력은 예전처럼 쓴다.
- 쓰기는 결과 폴더에만 한다. 다른 폴더에 쓰거나 기존 파일을 고치는 일은 아직 하지 않는다 (필요하면 R3 승인과 함께).
