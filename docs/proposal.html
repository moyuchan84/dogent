1배경

시스템은 많고, 그 사이를 사람이 손으로 잇고 있습니다.

반복되는 화면 작업

조회 조건 입력, 엑셀 내려받기, 필터링, 다른 화면에 붙여넣기. 판단보다 손이 더 많이 가는 일이 매일 반복됩니다.

기존 RPA의 한계

화면 좌표와 고정 스크립트에 의존해, 화면이 조금만 바뀌어도 멈춥니다. 만들고 고치는 일이 개발자 몫입니다.

달라진 조건

사내에 Gemma API가 제공되고, 브라우저를 조작하는 AI 에이전트 방식이 검증되었습니다. 데이터를 밖으로 내보내지 않고 같은 방식을 시도할 수 있습니다.

2컨셉

모델에게 전부 맡기지 않습니다. 절차는 사람이 정하고, 모델은 화면을 읽고 단계를 수행합니다.

스킬 = 업무 절차서

"재공 조회 화면으로 이동 → 라인 선택 → 조회 → 표 추출"처럼 현업이 쓰는 말로 적은 문서입니다. 화면이 바뀌면 문서만 고치면 되고, 프로그램을 다시 배포하지 않습니다.

화면을 글자로 읽는다

화면을 이미지가 아니라 "버튼: 조회", "선택 상자: 라인" 같은 목록으로 바꿔 모델에 줍니다. 좌표에 의존하지 않아 화면 배치가 바뀌어도 버팁니다.

데이터는 PC 밖으로 나가지 않는다

표 데이터의 집계·가공은 PC 안에서 계산합니다. 모델에는 컬럼 이름과 샘플 몇 행만 전달하므로 숫자가 틀릴 일이 없고 유출 위험도 줄어듭니다.

되돌릴 수 없는 일은 사람이 누른다

저장·상신·삭제 전에는 반드시 내용을 요약해 보여주고 사용자 승인을 받습니다. 기존 결재 절차는 그대로 유지됩니다.

3유즈케이스

조회성 업무로 시작해, 입력과 신청 업무로 넓힙니다.

UC-01 Phase 1 · PoC조회만

재공(WIP) 확인

"8라인 PHOTO 공정 재공 확인해줘" 한 줄로 조회부터 정체 Lot 정리까지.

  1. 사용자가 라인·공정을 말로 지시
  2. 재공 조회 화면 이동, 조건 입력, 조회
  3. 결과 표 전체 추출
  4. 기준 초과 Lot 필터, 공정별 집계
  5. 요약 표시, 엑셀 저장
UC-02 Phase 2조회만

웹 → 엑셀 내보내기 및 가공

조회 결과를 내려받아 정해진 양식으로 가공합니다. 가공 전후의 행 수와 합계를 검증해 보여줍니다.

  1. 대상 화면 조회
  2. 엑셀 다운로드 또는 표 추출
  3. 가공 명세 작성 (필터·집계·병합)
  4. PC에서 가공 실행, 검증
  5. 미리보기 후 저장
UC-03 Phase 2저장 포함

엑셀 → 웹 일괄 입력

엑셀에 정리한 데이터를 웹 화면에 옮깁니다. 입력한 값을 다시 읽어 원본과 100% 일치할 때만 저장을 요청합니다.

  1. 엑셀 파일과 대상 화면 지정
  2. 컬럼 매핑, 형식 검증
  3. 일괄 붙여넣기 또는 행별 입력
  4. 화면 값을 원본과 대조
  5. 대조 결과 확인 후 저장 승인
  6. 저장
UC-05 Phase 2상신 포함

IP 방화벽 해제 신청

신청서 작성과 상신까지만 대행합니다. 승인은 기존 결재 라인이 그대로 수행하며, 넓은 대역이나 전체 포트 같은 금지 패턴은 사이트에 접속하기 전에 차단합니다.

  1. 출발지·목적지·포트·기간·사유 지시
  2. 형식 및 금지 패턴 검증
  3. 신청 사이트 접속, 신청서 작성
  4. 작성 내용을 요청과 대조
  5. 요약 확인 후 상신 승인
  6. 상신, 신청 번호 기록
UC-04 Phase 3

다중 시스템 결합 리포트

재공 현황과 설비 상태처럼 두 시스템의 데이터를 조회해 결합하고, 리포트 양식에 채웁니다.

UC-06 Phase 3

정기 실행 리포트

매일·매주 같은 조회와 가공을 정해진 시각에 실행합니다. 조회성 스킬만 등록할 수 있습니다.

상세 흐름과 예외 처리는 01-usecases.md에 있습니다.

4동작 방식

한 단계마다 보고, 정하고, 검사하고, 실행하고, 확인합니다.

  1. 관찰
    현재 화면을 요소 목록으로 변환
  2. 판단
    스킬의 현재 단계에 맞는 동작을 Gemma가 선택
  3. 검사
    허용 사이트·허용 동작인지 규칙으로 확인
  4. 승인
    저장·상신이면 사용자 확인
  5. 실행
    클릭·입력·추출
  6. 검증
    스킬에 적힌 확인 조건 통과 여부

쓸수록 빨라집니다

한 번 성공한 경로는 저장해 두고 다음부터 모델 호출 없이 재생합니다. 화면이 바뀌어 실패할 때만 모델이 다시 화면을 읽어 복구합니다.

모르면 멈춥니다

입력이 부족하면 추측하지 않고 묻습니다. 스킬에 없는 상황을 만나면 임의로 진행하지 않고, 어디까지 했는지 보고하고 중단합니다.

6배포·운영

기존 사내 배포 체계를 그대로 씁니다.

설치와 업데이트

  • 확장: 브라우저 정책으로 대상 PC에 자동 설치·업데이트
  • 클라이언트: 서명된 MSI, 사내 파일 서버에서 자동 업데이트
  • 개발팀 → 파일럿 부서 → 전체 순으로 단계 배포

스킬 관리

  • 사내 Git에 올리고 업무 오너가 검토 후 배포
  • 화면이 바뀌면 스킬 문서만 수정
  • 성공률이 떨어진 스킬은 오너에게 자동 알림

운영 통제

  • 스킬별 실행 수, 성공률, 소요 시간 집계
  • 문제 발생 시 특정 스킬 또는 전체를 원격으로 즉시 중지
  • 모델 버전 변경 전 회귀 테스트

7보안·통제

에이전트는 사용자가 할 수 있는 일만, 사용자가 보는 앞에서 합니다.

8로드맵

단계마다 판정 기준을 두고, 통과할 때만 다음으로 갑니다. 기간은 추정치입니다.

Phase 0 · 1~2주

사전 확인

  • Gemma API 스펙·속도 실측
  • 보안 정책 협의
  • 대상 화면 구조 조사
  • 현재 업무 소요 시간 측정
판정 전제 조건 충족 여부
Phase 1 · 3~4주

PoC

  • 재공 확인 1건
  • 확장 단독 구성
  • 화면 읽기, 에이전트 루프, 표 추출
판정 20회 반복 성공률 90% 이상, 데이터 100% 일치
Phase 2 · 6~8주

MVP

  • 엑셀 ↔ 웹, 방화벽 신청
  • 승인 게이트, 입력 대조
  • 스킬 형식·검토 절차 확정
  • 스킬 제작 체계: 녹화로 초안, 품질 검사, 시험 실행
판정 4개 업무 성공률 90% 이상, 승인 없는 제출 0건
Phase 3 · 8주

파일럿

  • 1개 부서 실사용
  • 데스크탑 클라이언트, Hub
  • 스케줄, 결합 리포트
판정 실측 절감 시간, 오제출 0건
Phase 4 · 지속

확산

  • 부서·스킬 확대
  • 스킬 오너 양성
  • API 연동으로 고도화

효과는 가정하지 않고 측정합니다

월 절감 시간 = (수작업 건당 시간 − 에이전트 사용 시 사람이 쓴 시간) × 월 실행 건수. 수작업 시간은 Phase 0에서 조사하고, 나머지는 실행 로그에서 산출합니다.

9리스크와 대응

가장 큰 불확실성 세 가지는 Phase 0에서 먼저 확인합니다.

리스크대응확인 시점
Gemma의 판단이 불안정절차는 스킬이 쥐고 모델 역할을 좁힘. 출력 검증·재시도, 성공 경로 재사용Phase 0~1
대상 화면이 전용 그리드 방식시스템별 어댑터 개발, 화면의 엑셀 다운로드 기능 활용, 스크린샷 보조Phase 0
확장 권한이 보안 정책에 막힘조기 협의, 권한을 줄인 축소 구성 준비Phase 0
잘못된 저장·상신승인 게이트, 입력 대조, 시험 실행 모드, 감사 로그Phase 2
화면 변경으로 스킬이 깨짐자가 복구, 성공률 모니터링, 스킬 오너 체계Phase 3~
수작업보다 느림성공 경로 재사용으로 모델 호출 축소Phase 1

10의사결정 요청 사항

PoC 종료 시점에 결과를 보고하고 계속 여부를 다시 판단받겠습니다.

  1. Phase 0~1 착수 승인 — 약 5~6주, 개발 인력 2명 (추정)
  2. PoC 대상 지정 — 재공 조회 시스템과 현업 담당자 1명
  3. 보안 부서 협의 창구 지정 — 확장 권한과 로그 범위 협의
