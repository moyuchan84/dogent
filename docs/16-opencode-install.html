opencode로 회사 PC 설치 자동화

회사 PC의 opencode에 Dogent 빌드·설치를 맡기는 안내입니다. 사람이 손으로 하는 순서는 15. 회사 PC 재설치 안내에 있고, 이 문서는 그 순서를 묻지 않고 멈추지 않는 명령으로 바꾼 것입니다. 같은 내용의 Markdown판은 16-opencode-install.md이며, opencode에는 그 파일을 읽게 합니다.

1 · 점검Node · pnpm · 설정 빈칸
2 · 빌드build.ps1 -Mode company -Test
3 · 설치install.ps1 -Quiet
4 · 확인파일 · 모드 · 연결 등록
5 · 사람확장 로드 · 패널 설정

무엇을 맡기나

누가하는 일
opencode 자동준비물 점검 → 빌드와 시험 → D:\Multimedia\Dogent에 설치 → 앱 실행 → 결과 확인 → 보고
사람 처음 한 번브라우저에 확장을 로드하고, 사이드 패널에서 연결 방식과 사용자 ID를 설정합니다. 브라우저 화면 조작이라 opencode가 할 수 없습니다.
전제: 저장소를 받았고, 저장소 루트에 .env.company.local을 채워 두었습니다.
설치 폴더가 D:\Multimedia\Dogent인 이유 — 사내 보안 프로그램(EDM/NASCA) 때문에 크롬은 D:\Multimedia 아래 폴더의 확장만 로드할 수 있습니다. 설치 프로그램은 D:\Multimedia가 있으면 그 아래에, 없으면 %LOCALAPPDATA%\Dogent에 설치합니다. 예전 %LOCALAPPDATA%\Dogent 설치는 새 설치가 정리합니다(내 스킬·설정은 %USERPROFILE%\.dogent라 그대로).

opencode에 넣을 요청

저장소 루트에서 opencode를 열고 아래를 그대로 붙여 넣습니다.

처음 설치

docs/16-opencode-install.md 를 읽고 "2. 에이전트 절차"를 순서대로 실행해 줘.
- 명령은 문서에 적힌 그대로 쓰고, 대화형 스크립트(.cmd)는 실행하지 마.
- .env.company.local 의 값은 화면에 출력하거나 커밋하지 마.
- 단계가 실패하면 "4. 실패했을 때" 표대로 한 번만 조치해 보고, 그래도 안 되면 멈추고 오류 메시지를 그대로 보여 줘.
- 끝나면 "5. 보고 양식"으로 보고해 줘.

업데이트만

docs/16-opencode-install.md 의 "3. 업데이트 절차"를 실행하고 "5. 보고 양식"으로 보고해 줘.

opencode가 지킬 규칙

  1. .cmd는 실행하지 않습니다끝에 pause나 timeout이 있어 멈춥니다. 항상 powershell -NoProfile -ExecutionPolicy Bypass -File install\*.ps1 …로 부릅니다.
  2. install.ps1은 반드시 -Quiet로빼면 Read-Host에서 입력을 기다리며 멈춥니다. build.ps1 -Install도 첫 설치에서는 확장 로드를 기다리며 멈추므로 쓰지 않습니다.
  3. 키를 출력하지 않습니다.env.company.local을 cat이나 Get-Content로 출력하지 않습니다. 빈칸 검사는 변수 이름만 찾습니다.
  4. 커밋하지 않을 것release\ 폴더와 .env.*.local은 .gitignore에 있습니다. git add -f를 쓰지 않습니다.
  5. 관리자 권한 없이필요하지 않습니다. 관리자 권한을 요구하는 조치는 하지 말고 멈춥니다.
  6. 셸저장소 루트에서 PowerShell로 실행합니다. 셸이 bash라면 각 명령을 powershell -NoProfile -Command "…"로 감쌉니다. powershell을 찾지 못하면 전체 경로 C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe를 씁니다.
  7. -Target을 넘기지 않습니다기본값(D:\Multimedia\Dogent)이어야 크롬이 확장을 로드할 수 있고, 예전 %LOCALAPPDATA%\Dogent 설치도 정리됩니다.

에이전트 절차 (처음 설치)

2-1. 준비물 점검

node -v                         # v22 이상이어야 한다
pnpm -v                         # 없으면: corepack enable pnpm  (그래도 없으면 npm install -g pnpm)
git status --short              # 저장소 루트인지 확인. 고친 파일이 있으면 보고에 적는다
Test-Path .env.company.local    # True 여야 한다
Test-Path "$env:SystemRoot\Microsoft.NET\Framework64\v4.0.30319\csc.exe"   # False면 오피스 도구만 뺀다
Test-Path D:\Multimedia         # True 여야 한다. False면 멈추고 보고 (그대로 설치하면 크롬이 확장을 못 읽는다)

2-2. 회사 설정 빈칸 검사 (값은 출력하지 않음)

Select-String -Path .env.company.local -Pattern '=\((api_base_url|credential_key|model|user_type)\)' | ForEach-Object { $_.Line.Split('=')[0] }
아무것도 나오지 않아야 합니다. 변수 이름이 나오면 멈추고 사람에게 채워 달라고 합니다. 이 상태로 빌드하면 스크립트가 메모장을 띄우고 실패합니다.

2-3. 빌드하고 배포 묶음 만들기

powershell -NoProfile -ExecutionPolicy Bypass -File install\build.ps1 -Mode company -Test
  • 확장, 터미널 클라이언트, 오피스 도구, 데스크탑 앱을 빌드하고 release\Dogent-company-<판>\에 묶습니다.
  • -Test는 typecheck와 단위 시험을 먼저 돌립니다. 실패하면 멈추고 실패한 시험 이름을 보고합니다. 시험 없이 설치만 급하면 사람에게 물은 뒤 뺍니다.
  • 처음에는 pnpm install과 Electron 다운로드로 수 분이 걸립니다. 명령 제한 시간을 10분 이상으로 잡습니다.
  • 마지막에 ✓ release\Dogent-company-<판>과 완료했습니다.가 나와야 합니다.

2-4. 이 PC에 설치

$ver = (Get-Content -Raw package.json | ConvertFrom-Json).version
powershell -NoProfile -ExecutionPolicy Bypass -File "release\Dogent-company-$ver\install.ps1" -Quiet

-Quiet라서 묻지 않고 브라우저와 앱도 띄우지 않습니다. 켜져 있던 Dogent 앱은 닫고 덮어씁니다. 출력에 브라우저에 확장 로드 안내가 나오는 것은 정상입니다. 그 단계는 사람이 합니다.

2-5. 앱 실행 (브라우저 연결 등록)

Start-Process "D:\Multimedia\Dogent\app\Dogent.exe"
Start-Sleep -Seconds 5
Get-Process Dogent -ErrorAction SilentlyContinue | Select-Object Id, StartTime

앱은 뜰 때마다 Native Messaging 호스트(com.dogent.bridge)를 스스로 등록합니다. 크롬이 띄우는 호스트 파일은 D:\Multimedia\Dogent\native\에 두고, 예전 위치(%USERPROFILE%\.dogent)에 남은 호스트 파일은 지웁니다. 토큰과 내 스킬·기록은 %USERPROFILE%\.dogent에 그대로 있습니다.

설치 확인 (2-6)

$d = "D:\Multimedia\Dogent"
'extension\manifest.json', 'app\Dogent.exe', 'dogent-office.exe', 'dogent.mjs', 'bin\dogent.cmd', 'build-info.txt', 'native\native-host.cmd', 'native\com.dogent.bridge.json' |
  ForEach-Object { '{0,-24} {1}' -f $_, (Test-Path (Join-Path $d $_)) }
Get-Content -Encoding UTF8 "$d\build-info.txt" -TotalCount 5      # "모드: company" 여야 한다
reg query "HKCU\Software\Google\Chrome\NativeMessagingHosts\com.dogent.bridge" 2>$null
reg query "HKCU\Software\Microsoft\Edge\NativeMessagingHosts\com.dogent.bridge" 2>$null
확인할 것기대 값
extension\manifest.json, app\Dogent.exe, dogent.mjsTrue
dogent-office.exeTrue (csc.exe가 없어 뺐으면 False가 맞음)
build-info.txt의 모드company
native\native-host.cmd, native\com.dogent.bridge.jsonTrue (앱이 뜬 뒤)
NativeMessagingHosts 레지스트리쓰는 브라우저 쪽 값이 D:\Multimedia\Dogent\native\com.dogent.bridge.json. 없으면 앱이 아직 등록 전이니 10초 뒤 다시 봅니다

사람이 할 일 (2-7, 처음 한 번)

opencode는 이 내용을 안내만 하고 끝냅니다.

  1. 확장 관리 화면 열기chrome://extensions (엣지는 edge://extensions)
  2. 예전 Dogent 삭제다른 폴더(…\dogent\.output\…, …\release\Dogent-…, 예전 설치 위치 …\AppData\Local\Dogent\extension)에서 로드한 Dogent가 있으면 삭제합니다.
  3. 확장 로드오른쪽 위 개발자 모드를 켜고 압축해제된 확장 프로그램을 로드합니다 → D:\Multimedia\Dogent\extension. 처음 한 번만 하면 됩니다.
  4. 연결은 저절로회사 빌드는 연결 방식이 처음부터 Native Messaging이고 토큰도 자동입니다. 30초 안에 연결되지 않으면 사이드 패널 설정 → 클라이언트 연결이 Native Messaging인지 보고 저장합니다. 사이드 패널 설정에서 사용자 ID와 조작할 사이트를 넣습니다.
  5. 연결 확인Dogent 앱 위쪽에 브라우저 이름이 보이면 연결된 것입니다.
  6. 화면 점검실제 업무 스킬을 돌리기 전에 대상 사내 화면을 열어 두고, 패널이 화면을 제대로 읽는지 먼저 확인합니다.

업데이트

확장을 D:\Multimedia\Dogent\extension에서 한 번 로드해 둔 PC라면 명령 하나입니다.

powershell -NoProfile -ExecutionPolicy Bypass -File install\update.ps1 -Mode company -Test
  • git pull --ff-only → 의존성이 바뀌었으면 pnpm install → 전부 빌드 → 덮어써 설치 → 켜져 있던 앱을 새 판으로 다시 띄웁니다.
  • 고친 파일이 있으면 pull을 건너뛰고 지금 코드로 빌드합니다. 고친 파일이 N개 경고가 보이면 보고에 적습니다.
  • git 없이 코드를 옮겨 온 PC면 -NoPull을 붙입니다.
  • 확장은 다시 로드하지 않습니다. 폴더의 새 판을 알아채고 1분 안에 스스로 다시 읽습니다.
  • Dogent를 다른 폴더(…)에서 로드해 두었습니다가 보이거나 확장 로드를 기다리며 멈추면, 확장이 아직 이 폴더에서 로드되지 않은 것입니다. 사람이 할 일을 안내합니다.
  • 끝나면 설치 확인을 다시 돌립니다.

실패했을 때

표대로 한 번만 조치합니다. 표에 없는 오류는 조치하지 말고 멈춘 뒤 마지막 30줄을 그대로 보여 줍니다.

출력에 보이는 것한 번 해 볼 조치
Node.js가 없습니다 / 22 이상이 필요합니다멈추고, 사내 소프트웨어 센터에서 Node.js LTS(22 이상) 설치를 요청
pnpm을 켜지 못했습니다npm install -g pnpm 후 새 셸에서 2-3 다시
채우지 않은 (…) 값이 있습니다멈추고 2-2에서 나온 변수를 채워 달라고 요청
pnpm install 실패 (ETIMEDOUT, ECONNREFUSED, 403)사내 npm 미러 주소를 받아 npm config set registry <주소> 후 2-3을 -Reinstall과 함께 다시
Electron 다운로드 실패미러가 있으면 $env:ELECTRON_MIRROR='<주소>' 후 다시. 없으면 -Parts extension,client,office로 데스크탑 앱을 빼고 보고에 적기
오피스 도구 빌드 실패 / csc.exe 없음-Parts extension,client,desktop으로 다시 (Excel 기능만 빠짐)
typecheck 실패 / 단위 시험 실패코드를 고치지 말고 멈춤. 실패한 파일·시험 이름과 메시지를 보고
확장 폴더를 복사하지 못했습니다 (robocopy …)확장 폴더를 연 탐색기 창을 닫아 달라고 요청한 뒤 2-4 다시
데스크탑 앱 폴더를 복사하지 못했습니다 (사용 중)Get-Process Dogent, dogent-office -ErrorAction SilentlyContinue | Stop-Process -Force 후 2-4 다시
확장과 앱이 연결되지 않음 (dogent doctor에 한 파일 실행본(portable exe))예전 묶음으로 설치한 것. 2-3부터 다시 빌드·설치하고 app\Dogent.exe를 띄움
실행 정책 오류명령에 -ExecutionPolicy Bypass가 빠졌는지 확인. 정책 자체는 바꾸지 않음
