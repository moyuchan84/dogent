# 06. 스킬 제작 체계

> 문서 상태: v0.1 (2026-10-13) · 구현 반영
> 대상: 스킬을 만드는 현업 엔지니어, 스킬을 검토하는 담당자

## 1. 풀려는 문제

스킬은 엔지니어가 자기 업무를 직접 적어야 늘어납니다. 그런데 사람마다 쓰는 방식이 다르면 다음 문제가 생깁니다.

| 문제 | 결과 |
|---|---|
| 단계를 글로만 적는다 ("조회한다") | 무엇을 누를지 모델이 정해야 해서 느리고, 모델에 따라 결과가 달라진다 |
| 끝났는지 확인하는 조건이 없다 | 조회가 끝나기 전에 다음 단계로 넘어가거나, 실패했는데 완료로 보고한다 |
| 저장·상신 버튼을 일반 단계처럼 적는다 | 승인 없이 제출될 수 있는 스킬이 만들어진다 |
| 형식을 외워야 쓸 수 있다 | 만드는 사람이 늘지 않는다 |

그래서 **만드는 방법, 품질 기준, 배포 조건**을 사람의 숙련도가 아니라 도구가 정하게 합니다.

## 2. 세 가지 장치

| 장치 | 하는 일 | 품질을 맞추는 방식 |
|---|---|---|
| **녹화로 초안 만들기** | 업무를 한 번 해 보이면 SKILL.md 초안이 나온다 | 모든 초안이 같은 형식으로 나온다. 형식을 외울 필요가 없다 |
| **품질 검사** | 스킬을 규칙으로 검사해 등급(A~F)을 매긴다 | 누가 만들었든 같은 규칙을 적용한다 |
| **배포 관문** | 검사 통과 + 시험 실행 통과여야 배포를 요청할 수 있다 | 돌려 보지 않은 스킬은 배포되지 않는다 |

## 3. 만드는 순서

```
① 녹화          ② 초안 확인         ③ 품질 검사        ④ 시험 실행          ⑤ 배포 요청
업무를 한 번  →  입력받을 값 고르기 →  등급 B 이상까지  →  다른 값으로 실행  →  SKILL.md를 Git에
해 보인다        표 읽기 추가         지적 사항 고치기     (R3는 상신 직전까지)   올려 검토받는다
```

### ① 녹화

1. 업무의 첫 화면을 연다 (로그인은 미리 해 둔다).
2. 사이드 패널 → **스킬 만들기** → 스킬 ID, 이름, 설명, 담당 부서를 적고 **녹화 시작**.
3. 평소대로 업무를 한 번 한다. 패널에 조작이 순서대로 쌓인다.
4. 표를 읽어 엑셀로 내려야 하면 그 화면에서 **화면의 표 읽기 추가**를 누르고 표를 고른다. 화면에 엑셀 내려받기 버튼이 있으면 그 버튼을 누르는 편이 낫다 (여러 페이지를 한 번에 받는다).
5. **녹화 끝**.

녹화되는 것은 클릭, 입력, 선택입니다. 비밀번호 칸은 녹화하지 않고, 로그인 화면에서는 시작되지 않습니다.

### ② 초안 확인

녹화 목록에서 조작마다 정합니다.

- **실행할 때마다 입력받기** (기본): 그 값이 스킬의 입력 항목이 된다. 예: 라인, IP, 사유.
- 끄면 녹화한 값을 고정해서 쓴다. 예: 늘 같은 프로토콜.
- 실수로 누른 것은 **빼기**.

초안은 다음을 자동으로 갖춥니다.

| 항목 | 내용 |
|---|---|
| 단계 형식 | 모든 단계가 `도구로 ...` + `` `{인자}` `` 형식. 모델을 부르지 않고 실행된다 |
| 검사 식 | 입력·선택은 `value("칸") == "값"`, 버튼은 `did("click")` + 누른 뒤 새로 나타난 글자 |
| 시작 화면 | `url("경로") and text("화면 제목")` |
| 입력 항목 | 입력 칸의 종류에 따라 string / number / text, 선택 상자는 enum과 옵션 목록 |
| 통제 선언 | 저장·상신 계열 버튼을 눌렀으면 `risk: R3`, `submit_steps`, `submit_labels` |
| 표 읽기 | `extract_table` → `write_excel`, 결과 문구의 행 수는 `{rows.데이터셋}` |
| 파일 내려받기 | "엑셀 다운로드" 같은 버튼을 누르면 그 단계가 `download_table`이 되어, 받은 파일을 읽어 `write_excel`로 저장한다 |

초안의 입력 이름은 `v1`, `v2`처럼 붙습니다. 화면에는 라벨(칸 이름)이 보이므로 그대로 써도 되고, 의미 있는 이름으로 바꿔도 됩니다.

### ③ 품질 검사

초안 화면 위쪽에 등급과 지적 사항이 나옵니다. SKILL.md를 고치면 바로 다시 검사합니다.

| 등급 | 기준 | 할 수 있는 것 |
|:-:|---|---|
| A | 오류 0, 경고 0 | 배포 요청 가능 |
| B | 오류 0, 경고 1~2 | 배포 요청 가능 (검토 때 경고 사유를 설명) |
| C | 오류 0, 경고 3 이상 | 내 PC에서만 사용 |
| F | 오류 1 이상 | 저장 불가 |

**오류** — 실행이 안 되거나 통제를 벗어날 수 있음

| 규칙 | 내용 |
|---|---|
| E01 | 문서 형식 오류 (선언부, 단계 절, 검사·기록 식) |
| E02 | 단계의 인자가 JSON이 아니거나 도구의 형식과 다름 |
| E03 | 선언하지 않은 입력 `{name}`, 앞에서 기록하지 않은 `{out.name}` |
| E04 | 저장·상신 버튼을 누르는데 R3 선언, `submit_steps`, `submit_labels`가 맞지 않음 |
| E05 | 앞 단계에서 만들지 않은 데이터셋을 사용 |
| E06 | `domains`에 없는 주소로 이동 |
| E07 | 이미 배포된 스킬과 같은 ID (패널에서만 검사) |

**경고** — 실행은 되지만 재현성이 떨어짐

| 규칙 | 내용 |
|---|---|
| W01 | 검사 식이 없는 단계 (끝났는지를 모델이 판단) |
| W02 | 도구와 인자가 적히지 않은 단계 (동작을 모델이 결정) |
| W03 | 버튼을 누른 뒤 무엇이 보여야 하는지가 없음 (`did("click")`뿐) |
| W04 | 선언만 하고 쓰지 않는 입력 |
| W05 | 마지막 단계가 `finish`가 아님 (결과 문구를 모델이 지음) |
| W06 | R3인데 `submit_labels`가 비어 있음 |
| W07 | R3인데 입력값 규칙(policy.yaml)이 없음 |
| W08 | `## 예외` 절이 없음 |
| W09 | `max_steps`가 단계 수의 2배 미만 |

경고는 "모델에 기대는 부분"을 가리킵니다. 화면 구조상 어쩔 수 없이 모델이 판단해야 하는 단계도 있으므로 2개까지는 허용하고, 검토 때 사유를 확인합니다.

### ④ 시험 실행

1. **초안으로 저장**하면 실행 탭의 스킬 목록에 `[초안]`으로 나타난다.
2. 녹화할 때와 **다른 값**을 넣고 실행한다. 저장·상신이 있는 스킬은 **시험 실행**을 켜서 제출 직전에 멈추게 한다.
3. 끝까지 돌면 그 초안은 "시험 실행 통과"로 기록된다. 내용을 고치면 기록이 지워지므로 다시 돌려야 한다.

초안은 만든 PC에만 있습니다. 허용 도메인, 승인, 입력 대조 같은 통제는 배포된 스킬과 똑같이 적용됩니다.

### ⑤ 배포 요청

**내 초안**의 세 항목이 모두 채워지면 배포를 요청할 수 있습니다.

- 형식·통제 오류 없음
- 품질 등급 B 이상
- 지금 내용으로 시험 실행 통과

SKILL.md를 내려받아 `skills/<id>/SKILL.md`로 넣고 검토를 올립니다. 병합된 뒤 `pnpm skill:index`로 목록을 다시 만들어 공유 스킬 저장소에 올리면, 확장을 다시 배포하지 않아도 모든 사용자의 목록에 `[공유]`로 나타납니다 (README의 "다시 빌드하지 않고 스킬 공유하기"). 저장소에서는 `pnpm skill:lint`가 같은 규칙으로 다시 검사하며, 번들된 스킬은 전부 A등급이어야 테스트가 통과합니다.

## 4. 검토자가 보는 것

도구가 형식과 통제 선언을 봐 주므로, 검토자는 도구가 판단할 수 없는 것만 봅니다.

| 확인 항목 | 이유 |
|---|---|
| 이 업무를 자동화해도 되는가, 담당 부서가 맞는가 | 업무 책임의 문제 |
| 입력받을 값과 고정한 값의 구분이 맞는가 | 고정하면 안 되는 값을 고정했을 수 있음 |
| R3 스킬의 policy.yaml 규칙이 충분한가 | 넣으면 안 되는 값은 업무 지식 |
| 예외 절이 실제 오류 상황을 다루는가 | 초안의 예외 절은 일반 문구 |
| 남은 경고의 사유 | 모델 판단이 꼭 필요한 단계인지 |

## 5. 손으로 쓸 때

녹화가 맞지 않는 업무(조건에 따라 갈라지는 절차, 데이터 가공이 많은 업무)는 틀에서 시작합니다.

```bash
pnpm skill:new my-skill "스킬 이름"   # skills/my-skill/SKILL.md 생성
pnpm skill:lint                       # 번들된 스킬 전체 검사
```

형식은 [05-skill-spec.md](05-skill-spec.md)를 따릅니다. 녹화로 만든 초안을 패널에서 내려받아 고쳐 쓰는 것이 가장 빠릅니다.

## 6. 지금 안 되는 것

| 항목 | 상태 |
|---|---|
| 표의 페이지 넘김 | 녹화로는 한 페이지만. `next_ref`를 손으로 더해야 함 (초안에 안내가 붙음). 엑셀 내려받기 버튼이 있는 화면은 그 버튼을 녹화하면 됨 |
| 표에 일괄 입력(`fill_table`), 가공(`transform`) | 녹화 대상이 아님. 손으로 추가 |
| 이름을 읽을 수 없는 요소, 같은 이름이 여럿인 요소 | 초안에 표시됨. 설명을 적으면 그 단계는 모델이 찾음 |
| 조건 분기 ("결과가 없으면 ...") | 예외 절에 글로 적음 |
| 초안 공유 | 만든 PC에만 있음. 공유는 Git 배포로 (Phase 3에서 동기화) |
| 화면 변경 감지 | 배포된 스킬이 깨졌는지는 실행 실패로만 알 수 있음 (Phase 3에서 성공률 모니터링) |
