1. 구조

판단·스킬·모델은 클라이언트가, 화면 조작은 브라우저 확장이 맡고 둘은 MCP로 잇습니다. 엑셀(문서 보안 NASCA)은 같은 클라이언트가 오피스 도구로 다룹니다.

데스크탑 앱 / 터미널 클라이언트 (Dogent.exe 하나)
  에이전트 루프 · 스킬 · 사내 Gemma 호출 · 승인 · 기록 · 예약
  ├─ 브리지 (같은 프로세스) ── Native Messaging / WebSocket ── 크롬·엣지 확장 ── 사내 웹
  │                                                            허용 사이트 · 저장/상신 승인 · 로그인은 사람이
  └─ dogent-office.exe (앱 안에 포함) ── Excel COM ── NASCA 문서 · EDM에서 연 문서

사용자가 설치하는 것은 앱 하나와 확장 하나입니다. 오피스 도구는 앱 안에 들어 있습니다. 같은 브리지에 Claude Code를 붙여 쓸 수도 있습니다.

3. 이번에 추가한 것

항목내용확인
확장 연결 자동 등록앱이 시작할 때 크롬·엣지 프로필에서 Dogent 확장을 찾아 Native Messaging 호스트를 등록. PC에 Node 불필요(앱을 ELECTRON_RUN_AS_NODE로 사용). 못 찾으면 설정에서 확장 ID 직접 입력. (bridge/register.mjs)e2e 통과 실제 프로필 탐지는 미확인
토큰 붙여넣기 제거Native Messaging 방식에서는 호스트가 토큰을 확장에 전달. WebSocket 방식만 토큰 필요e2e 통과
사용자 ID 자동llm.userId를 안 적으면 로그인한 Windows 계정으로 모델 API 헤더 User-Id를 채움. 설정값이 있으면 그 값 우선게이트웨이 일치 여부 사내 확인
모델 API 바쁠 때 재시도429/502/503/504면 Retry-After(없으면 2·4·8초)만큼 쉬고 최대 3번 재시도. 여러 사람이 같은 게이트웨이를 쓸 때 대비테스트 통과
예약 실행dogent schedule add|list|remove. Windows 작업 스케줄러에 등록, 로그인해 있을 때만 실행, 저장·상신은 하지 않음(--allow-write 없음)등록·조회·삭제 실측 실제 실행은 미확인
말로 스킬 만들기지금 브라우저 화면을 보고 초안 → 말로 고치기 → 시험 실행 → 개인 스킬로 저장. 터미널 dogent skill new와 앱 버튼 (src/core/compose.ts)e2e 통과 사내 모델 품질은 미확인
스킬 찾기스킬에 tags를 적고, 이름·태그·설명으로 찾음(조사·어미가 붙어도). dogent skills search [<말>], skills info <ID>(입력·위험도·담당·이 PC 성공률). 말이 없으면 지금 브라우저 화면의 사이트용 스킬. 앱은 검색창과 맨 위 "지금 화면" 묶음. 맞는 스킬이 없으면 말로 만들기로 안내 (src/core/catalog.ts)테스트·e2e 통과
팀 스킬 저장소를 주소로 받기teamSkillsUrl(빌드의 WXT_SKILLS_URL)의 index.json에서 git 없이 한 시간마다 받아 ~/.dogent/team-cache에 둠. 닿지 않으면 받아 둔 것을 씀. git clone 폴더(teamSkills)가 있으면 같은 ID는 그쪽 우선 (client/src/team.ts)e2e 통과 사내 GitHub 주소·토큰 방식 미확인

4. 아직 구현하지 않은 것

항목이유 / 필요한 것
EDM 스킬실제 EDM 화면이 필요. 버튼이 Excel을 여는 방식(내려받기, ms-excel: 링크, 전용 프로그램)에 따라 달라짐. 도구(excel_attach)는 이미 있음
구형 xls 읽기검증되지 않은 라이브러리를 넣거나, 확장에서 받은 파일을 클라이언트의 Excel로 넘기는 구조 변경이 필요. 사내에서 xls가 실제로 나오는지 먼저 확인
스크린샷 보조 입력, chrome.debugger 입력사내 화면에서 snapshot이 실패하는 경우를 보고 정할 일
Hub정책 배포·기록 수집·kill switch. 서버 위치, 인증, 운영 주체를 먼저 정해야 함
스킬 제작 확장표 페이지 넘김·일괄 입력 녹화, 초안 공유 동기화, 성공률로 화면 변경 감지. 사내 표 구조를 본 뒤 설계
사이드 패널 줄이기, 앱 화면의 예약 메뉴앱·확장이 사내에서 검증된 뒤. 예약은 지금 CLI에만 있음

5. 구현했지만 사내에서 확인되지 않은 것

항목위험확인 방법
사내 화면 호환성가장 큼 iframe, canvas 그리드, shadow DOM에서 snapshot이 요소를 못 잡을 수 있음확장의 "화면 점검" 보고서
사내 Gemma 도구 호출큼 JSON 출력·다단계 판단이 불안정하면 자유 요청이 막힘. 집에서는 Ollama·모의 모델로만 시험화면 하나에서 조회 1건을 자유 요청으로 실행
NASCA 재암호화중 Excel이 저장한 파일을 문서 보안이 다시 암호화하는지 모름. 지금 확장이 만드는 엑셀은 암호화되지 않음dogent excel resave <원본> <새 경로> 후 다른 PC에서 열기
크롬 Native Messaging 정책중 정책으로 막히면 WebSocket(토큰 필요)으로chrome://policy
확장 설치 방식중 압축해제 설치가 막히면 정책 배포와 확장 ID 고정 필요보안 부서 협의
휴대용 실행본의 호스트 기동중 실행할 때마다 압축을 풀어 느릴 수 있음사내 PC에서 확장 연결 시간 측정
같은 PC를 여러 명이 쓰는 환경중 브리지 포트 39217이 PC에서 하나뿐이라 두 번째 사용자 앱이 못 뜸원격 데스크톱 공용 PC가 있는지 확인
모델 API 키 공유중 키가 빌드에 들어가 모두가 같은 키. 사용자 구분은 User-Id 헤더로만개인별 토큰 발급 가능 여부

6. 여러 명이 같은 Gemma API를 쓸 때

  • API는 요청마다 메시지 전체를 보내는 방식이라 서버에 대화 세션이 없습니다. 대화 기록은 각자 PC의 앱 메모리와 ~/.dogent에만 있어 섞이지 않습니다.
  • 서버에서 사용자를 구분하는 것은 요청 헤더(User-Id, Send-System-Name, 요청마다 새로 만드는 uuid)입니다.
  • 몰리면 429가 올 수 있어 재시도를 넣었습니다. 게이트웨이의 실제 한도는 사내에서 확인해야 합니다.

7. 다음 순서

  1. 사내 PC에 앱과 확장을 설치하고 화면 점검 보고서와 조회 1건(자유 요청)을 실행합니다. 5번 항목 대부분이 한 번에 드러납니다.
  2. 막힌 곳이 화면 구조면 xls, 스크린샷 입력, 녹화 확장을, 모델이면 프롬프트·재시도를 손봅니다.
  3. EDM 스킬과 NASCA 저장은 실제 화면에서 이어서 합니다.
  4. 사용자가 늘면 Hub와 개인별 모델 토큰을 정합니다.
