Dogent 설치 안내

브라우저 확장 · 데스크탑 앱 · 오피스 도구 · 터미널 클라이언트를 Windows PC에 한 번에 설치합니다. 관리자 권한은 필요 없습니다.

배포 담당자build.cmd 로 빌드 → 배포 묶음(zip)
사용자 1zip을 풀고 install.cmd
사용자 2브라우저에 확장 폴더 로드
사용자 3앱 실행 → 연결 방식 Native Messaging

무엇이 설치되나

브라우저 확장extension\

업무 화면을 읽고 조작합니다. 사이드 패널, 승인 창, 조작할 사이트 목록을 지킵니다. 크롬·엣지에 로드합니다.

데스크탑 앱Dogent.exe

말로 요청하고 스킬을 실행하는 창. 확장과의 연결(Native Messaging)을 첫 실행에 스스로 등록합니다. Node가 없어도 됩니다.

오피스 도구dogent-office.exe

사용자의 Excel로 문서 보안(NASCA) 문서, EDM에서 연 문서를 읽고 씁니다. Excel이 설치된 PC에서만 씁니다.

터미널 클라이언트dogent.mjs · dogent 명령

앱과 같은 엔진의 명령줄 판. 예약 실행(dogent schedule)에 씁니다. Node.js 22 이상이 있어야 합니다.

설치하면 이렇게 놓입니다.

%LOCALAPPDATA%\Dogent\          ← 프로그램 (업데이트할 때 같은 곳에 덮어씀)
  extension\                    ← 브라우저에 로드하는 폴더. 경로가 바뀌면 확장 ID가 바뀝니다
  Dogent.exe  dogent-office.exe  dogent.mjs
  bin\dogent.cmd                ← dogent 명령 (PATH에 더함)
  설치안내.html  uninstall.cmd
%USERPROFILE%\.dogent\          ← 내 스킬·설정·실행 기록·연결 토큰 (제거해도 남음)

사용자
설치하기

  1. 배포 묶음을 받아 풉니다

    담당자에게 받은 Dogent-company-<판>.zip을 아무 폴더에나 풉니다 (예: 바탕화면). 압축을 푼 뒤 실행해야 합니다. zip 안에서 바로 누르면 파일을 찾지 못합니다.

  2. install.cmd를 두 번 누릅니다

    파란 창이 뜨고 순서대로 진행합니다: 프로그램 복사 → 바탕화면·시작 메뉴 바로 가기 → 확장 로드 안내 → 앱 실행.

    "Windows의 PC 보호" 창이 뜨면 추가 정보 → 실행을 누릅니다. Dogent가 켜져 있으면 닫을지 묻습니다.

  3. 브라우저에 확장을 로드합니다

    스크립트가 확장 관리 화면(chrome://extensions, edge://extensions)을 열고, 확장 폴더 경로를 클립보드에 넣어 둡니다.

    1. 오른쪽 위(엣지는 왼쪽 아래) 개발자 모드를 켭니다
    2. 압축해제된 확장 프로그램을 로드합니다 → 폴더 칸에 Ctrl+V → 폴더 선택
    3. 툴바의 퍼즐 조각 아이콘에서 Dogent를 고정(핀)합니다

    창으로 돌아가 Enter를 누르면 로드됐는지 확인합니다. 크롬과 엣지를 모두 쓰면 둘 다 로드합니다.

  4. 앱이 뜨면 끝

    스크립트가 Dogent 앱을 띄웁니다. 앱은 처음 뜰 때 로드된 확장을 찾아 브라우저 연결을 등록합니다. 다음부터는 바탕화면의 Dogent로 켭니다.

처음 한 번 설정

  1. 확장을 앱에 연결합니다

    브라우저에서 Dogent 아이콘 → 사이드 패널 → 설정 → 클라이언트 연결 → 방식 Native Messaging → 연결 설정 저장. 토큰은 자동으로 전달되므로 비워 둬도 됩니다.

    앱 위쪽에 브라우저 이름(크롬, 엣지)이 보이면 연결된 것입니다. 크롬과 엣지를 모두 연결했으면 둘 다 보이고 골라 씁니다.

    패널에 "pnpm bridge:install을 실행하라"는 안내가 보여도 무시해도 됩니다. 앱이 같은 일을 대신 했습니다.

  2. 모델 연결을 시험합니다

    사이드 패널 → 설정 → 연결 시험 → "연결됨". 사용자 ID 칸에는 사내 SSO ID를 넣습니다 (데스크탑 앱과 dogent 명령은 Windows 로그인 계정을 사용자 ID로 씁니다. 다르면 앱의 설정에서 고칩니다). "닿지 못했습니다"가 나오고 이 주소 접근 허용 버튼이 보이면 누릅니다.

  3. 업무 화면을 점검합니다

    업무 화면을 열고 패널 위쪽 화면 점검을 누릅니다. 조작할 사이트 목록에 없으면 이 사이트 허용을 누릅니다. 읽지 못하는 iframe, 그림으로 그린 그리드처럼 막히는 곳을 미리 알려 줍니다.

문제가 생기면 화면 점검 보고서(.md)나 기록 탭의 실행 기록을 내보내 담당자에게 보내 주세요. 보고서는 기본으로 화면 글자와 입력값을 가립니다.

업데이트

확장을 저장소의 빌드 폴더에서 로드해 쓰던 회사 PC를 이 방식으로 옮기는 순서는 회사 PC 재설치 안내에 따로 있습니다.

코드를 받아 빌드하는 PC(git으로 받은 저장소가 있는 PC)는 install\update.cmd를 두 번 누르면 끝납니다.

  1. git pull로 새 코드를 받습니다 (고친 파일이 있으면 받지 않고 지금 코드로 빌드). 의존성이 바뀌었으면 pnpm install도 합니다.
  2. 확장, 데스크탑 앱, 오피스 도구, 터미널 클라이언트를 모두 빌드해 %LOCALAPPDATA%\Dogent에 덮어씁니다. 켜져 있던 앱은 닫았다가 새 판으로 다시 띄웁니다.
  3. 브라우저 확장은 지우거나 다시 로드하지 않습니다. 확장이 폴더의 새 판을 알아채고 1분 안에 스스로 다시 읽습니다. Dogent 패널을 열면 바로 바뀝니다(패널이 한 번 닫힙니다). 실행 중이면 끝난 뒤에 바뀝니다.

모드는 지난번 것을 씁니다(처음은 company). 바꾸려면 update.cmd -Mode home, 코드를 직접 옮겨 왔으면 update.cmd -NoPull.

처음 한 번만: 확장을 %LOCALAPPDATA%\Dogent\extension에서 로드해 두어야 합니다. 저장소의 .output\…이나 release\Dogent-… 폴더에서 로드해 두었다면 확장 관리 화면에서 그 Dogent를 한 번 삭제하고 %LOCALAPPDATA%\Dogent\extension을 로드합니다(update가 알려 줍니다). 그 뒤로는 지울 일이 없습니다.

묶음을 받아 쓰는 PC는 새 묶음을 풀고 install.cmd를 다시 누릅니다. 같은 폴더에 덮어쓰고, 확장은 위와 같이 스스로 새 판으로 바뀝니다.

내 스킬, 실행 기록, 연결 토큰(%USERPROFILE%\.dogent)은 업데이트해도 바뀌지 않습니다.

제거

시작 메뉴 → Dogent → Dogent 제거. 프로그램, 바로 가기, dogent 명령, 브라우저 연결 등록을 지웁니다. 확장은 브라우저의 확장 관리 화면에서 삭제를 직접 누릅니다.

내 스킬·설정까지 지우려면 설치 폴더에서:

uninstall.cmd -Purge

집(Ollama)에서 시험할 때는 -Mode home(.env.home.local), 모의 모델로 흐름만 볼 때는 -Mode dev. 묶음 이름에 모드가 붙어 섞이지 않습니다.

하나씩 빌드하기

build.cmd가 부르는 명령과 같습니다. 한 부분만 고쳤을 때 씁니다.

부분명령 (회사)결과
확장pnpm build:company.output\chrome-mv3-company\
터미널 클라이언트pnpm client:build:companyclient\dist\dogent.mjs
오피스 도구pnpm office:buildoffice\dist\dogent-office.exe
데스크탑 앱pnpm desktop:pack:company (오피스 도구를 먼저 빌드해야 실행본에 들어감)desktop\release\Dogent-<판>.exe
시험pnpm typecheck · pnpm test · pnpm e2e:desktop

부분만 다시 묶으려면 -Parts를 씁니다. 빌드하지 않은 부분은 마지막으로 만든 결과물을 그대로 넣습니다.

install\build.cmd -Mode company -Parts extension,desktop -Zip

Claude Code에 붙여 쓰는 개발 PC라면 묶음 없이 등록만 합니다.

claude mcp add dogent -- node D:/code/samsung/dogent/bridge/hub.mjs
claude mcp add dogent-office -- D:\code\samsung\dogent\office\dist\dogent-office.exe

문제 해결

증상원인과 조치
개발자 모드가 회색이거나 로드가 막힘회사 크롬 정책(DeveloperToolsAvailability, ExtensionInstallBlocklist)이 압축해제 확장을 막고 있습니다. chrome://policy에서 확인하고, 엣지로 시도하거나 IT에 허용(또는 사내 배포 등록)을 요청합니다.
터미널 dogent가 "확장이 연결되기를 기다립니다…"에서 멈춤터미널에서 dogent doctor를 실행합니다. 토큰, 포트 39217 점유, 호스트 등록, 크롬·엣지 정책(NativeMessagingBlocklist, NativeMessagingUserLevelHosts), 호스트 실행, 그리고 15초 실시간 시험까지 한 번에 보여 주고 원인을 알려 줍니다. Native Messaging 방식인데 호스트가 등록되어 있지 않으면(터미널 dogent는 등록하지 않습니다) dogent doctor --fix 후 확장의 "연결 설정 저장"을 다시 누릅니다. 회사 정책이 막으면 확장의 방식을 WebSocket으로 바꾸고 dogent token의 값을 넣습니다.
앱 위쪽에 브라우저가 안 보임① 패널 설정의 연결 방식이 Native Messaging인지, 저장했는지 ② 확장을 앱보다 나중에 로드했다면 앱을 다시 켭니다 (켜질 때 확장을 찾아 등록) ③ 브라우저를 완전히 닫았다 다시 엽니다.
업데이트했는데 확장이 옛 판 그대로확장을 %LOCALAPPDATA%\Dogent\extension이 아닌 다른 폴더에서 로드했습니다. 그 Dogent를 지우고 이 폴더를 한 번 로드합니다. 맞는 폴더라면 Dogent 패널을 열면 바로 바뀝니다. 그래도 그대로면 확장 관리 화면에서 새로고침 ↻을 한 번 누릅니다.
업데이트 뒤 연결이 끊김확장 폴더를 다른 곳에 로드해 확장 ID가 바뀌었습니다. 확장 관리 화면의 Dogent가 %LOCALAPPDATA%\Dogent\extension을 가리키는지 보고, 아니면 지우고 그 폴더로 다시 로드한 뒤 앱을 다시 켭니다.
앱과 터미널을 함께 켜면 연결이 안 됨브리지 포트(39217)가 겹칩니다. 터미널 클라이언트, 데스크탑 앱, Claude Code의 브리지 중 하나만 켭니다.
install.cmd 창이 바로 닫힘zip 안에서 눌렀습니다. 압축을 풀고 다시 누릅니다. 그래도 닫히면 명령 창에서 install.cmd를 쳐서 메시지를 봅니다.
"스크립트를 실행할 수 없습니다".ps1을 직접 눌렀습니다. 같은 이름의 .cmd를 누릅니다 (실행 정책을 이번 실행에만 우회).
dogent 명령이 없음PATH는 새로 연 창부터 적용됩니다. 창을 다시 엽니다. Node.js가 없으면 터미널 클라이언트는 돌지 않습니다 (앱은 됨).
Excel 문서를 못 엶묶음에 dogent-office.exe가 있는지(build-info.txt), Excel이 설치돼 있는지 봅니다. 문서 보안 프로그램이 Excel 창을 요구하면 환경 변수 DOGENT_OFFICE_VISIBLE=1.
빌드: pnpm install이 node_modules를 지우겠다며 멈춤저장소의 잠금 파일은 pnpm 9로 만들었습니다. 다른 판(예: 11)이면 node_modules를 다시 깔려고 합니다. 명령 창에서 Y로 답하거나 npm install -g pnpm@9. 빌드 단계는 pnpm을 거치지 않으므로 판과 상관없습니다.
빌드: Electron을 내려받지 못함사내망. set ELECTRON_MIRROR=<사내 미러>/electron/ 후 install\build.cmd -Reinstall.
빌드: csc.exe를 찾지 못함.NET Framework 4.x가 꺼져 있습니다. Windows 기능에서 켜거나 DOGENT_CSC에 컴파일러 경로를 줍니다. 오피스 도구 없이 묶으려면 -Parts extension,client,desktop.
빌드: WXT_LLM_HEADERS 오류헤더 틀이 JSON 한 줄이 아닙니다. 줄 전체를 작은따옴표로 감쌌는지, 자리표시자가 {key} {userId} {userType} {systemName} {uuid}뿐인지 봅니다.
