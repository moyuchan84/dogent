# Dogent 사용 유즈케이스 가이드

> 기준일 2026-11-09 · "무엇을 어떻게 말하면 어떻게 돌고, 어디서 사람이 개입하는가"를 시나리오별로 정리했습니다.
> 업무 정의서(UC-01~07)는 [01-usecases.md](01-usecases.md), 안전 등급 정의도 거기에 있습니다. 설치는 [24](24-install-manual.md), 서버 준비는 [25](25-infra-setup.md).
> 시나리오의 시스템·화면 이름은 **모의 사이트·예시** 기준입니다. 사내 화면에서의 실제 동작은 아직 확인하지 못했습니다 ([27-gaps-and-improvements.md](27-gaps-and-improvements.md)).

## 1. 먼저 알아둘 것

### 1-1. 쓰는 방법 세 가지

| 방법 | 언제 | 예 |
|---|---|---|
| 데스크탑 앱 | 평소에 | 앱 입력창에 "7라인 재공 확인해줘" |
| 터미널 | 예약·자동화, 개발자 | `dogent "7라인 재공 확인해줘"` |
| 크롬 사이드 패널 | 클라이언트 없이 확장만으로 | 패널의 스킬 목록에서 실행 |

### 1-2. 위험 등급과 사람의 역할

| 등급 | 하는 일 | 통제 |
|---|---|---|
| R0 조회 | 화면 읽기, 표 추출, 내려받기 | 자동 |
| R1 파일 | 로컬 파일 저장 | 자동, 저장 위치 알림 |
| R2 입력 | 양식 채우기 (제출 전) | 입력값 정책 검사 + 입력 후 화면 값 대조 |
| R3 저장·상신 | 신청, 저장, 결재 | **승인 창** 필수, 시험 실행 가능, 단계당 1회 |

로그인은 항상 사람이 합니다. 비밀번호 칸이 보이면 멈추고 알립니다.

### 1-3. 자주 쓰는 입력 형태

```
dogent "7라인 재공 확인해줘"                  # 말로 (스킬을 고르고 값을 뽑음)
dogent run wip-check line=7라인               # 스킬을 직접
dogent "…" --dry-run                          # 저장·상신 직전에 멈춤
dogent "…" --allow-write                      # 자유 요청에서 저장·상신 허용 (승인 창은 그대로)
dogent -c "방금 결과를 라인별로 나눠줘"          # 대화 이어서
계획: MES에서 7라인 재공 내려받아 엑셀로 정리      # 계획을 먼저 보고 확인 후 실행
/wip-check 7라인                              # 대화창에서 스킬 바로 부르기
```

## 2. 시나리오

### 시나리오 1. 재공 조회 (R0~R1)

- **누가:** 라인 담당 엔지니어 · **언제:** 아침 라인 점검
- **말:** "7라인 재공 확인해줘"
- **흐름:** 시스템 사전에서 "재공" 시스템을 찾음 → 열린 탭이 없으면 주소를 열지 묻고 새 탭에서 시작 → 조회 조건 입력 → 페이지를 넘기며 추출 → 정체 Lot·공정별 집계 → 엑셀(원본 / 정체Lot / 공정별집계)
- **사람이 하는 일:** 로그인(필요할 때), 결과 확인
- **결과:** 저장 폴더(기본 내려받기)에 `재공확인_7라인.xlsx`, 앱에 요약
- **변형:** 화면에 "엑셀 다운로드" 버튼이 있으면 `wip-download`가 페이지를 넘기지 않고 한 번에 받음
- **안 될 때:** 0건이면 조건을 그대로 보여 주고 끝냄(임의로 조건을 바꿔 재조회하지 않음). 화면을 못 읽으면 **화면 점검** 먼저.

### 시나리오 2. 승인이 필요한 신청 — IP 방화벽 해제 (R3)

- **말:** "IP 방화벽 해제 신청해줘, 출발지 10.1.2.3, 목적지 …, 사유 …"
- **흐름:** 입력값 정책 검사(허용 대역·금지 포트·사유 길이) → 신청서 채움 → 화면 값과 입력값 대조 → **승인 창** → 상신
- **사람이 하는 일:** 승인 창의 내용을 화면과 비교하고 승인. 창을 닫으면 누르지 않음.
- **처음에는 반드시** `--dry-run`(또는 앱의 "시험 실행")으로 상신 직전 멈춤을 확인.
- **결과:** 신청 번호가 결과에 기록됨

### 시나리오 3. 엑셀 → 웹 일괄 입력 (R3)

- **말:** "재공 수량 조정 입력" 스킬 선택 + 엑셀 파일 지정 (첫 행: Lot ID, 공정, 조정수량, 사유)
- **흐름:** xlsx 읽기(보안 파일이면 Excel을 거쳐 열기) → **전체 행 사전 검사** → 입력 → 저장 전 대조 → 승인
- **묶어 실행:** 행마다 같은 스킬을 돌리며 **행마다 승인**, 행별 결과를 엑셀로
- **주의:** 단건이 안정된 뒤에 묶음으로 ([22-first-skills-playbook.md](22-first-skills-playbook.md) 6장)

### 시나리오 4. 스킬이 없는 화면을 말로 시키기 (자유 요청 → 스킬 저장)

- **말:** "이 화면에서 7라인을 조회해서 몇 건인지 알려줘"
- **흐름:** 모델이 화면을 읽고 한 단계씩 판단·실행 (정책 검사 → 확장이 실행)
- **잘 되면:** 결과 아래 "이 실행을 스킬로 저장" → 요청에 나온 값은 매개변수로, 요청은 마지막 목표 단계로 → 개인 스킬(`~/.dogent/skills`)
- **스킬 만드는 세 가지:** 말로 만들기 / 녹화(업무를 한 번 해 보임) / 잘 된 요청을 저장. 품질 B 이상 + 시험 실행 통과 후 팀 저장소 PR.

### 시나리오 5. 사내 MCP 도구로 처리 (브라우저 없이) — **새 기능**

- **준비:** 담당 팀이 MCP 서버를 올리고 카탈로그에 등록 ([25](25-infra-setup.md) 3장)
- **설치:** `dogent mcp browse` → `dogent mcp install mes-lots` (내용을 보고 확인)
- **말:** "MES에서 7라인 Lot 목록 보여줘" — 카탈로그의 `keywords`(MES, Lot, 재공 …)가 요청에 있으면 브라우저를 거치지 않고 서버 도구를 부름
- **바꾸는 도구(`lot_hold` 등):** `ask`이므로 부르기 전에 사람에게 묻고 승인해야 실행
- **권한 조정:** `dogent mcp allow|ask|deny <서버> <도구>`

### 시나리오 6. 훅으로 감사 기록·정책 검사 — **새 기능**

`%USERPROFILE%\.dogent\hooks.json`:

```json
{ "hooks": {
  "PreToolUse":  [{ "matcher": "excel_write|excel_save", "command": "node D:\\hooks\\check.mjs" }],
  "PostToolUse": [{ "command": "type con >> %USERPROFILE%\\.dogent\\audit.log" }],
  "Stop":        [{ "command": "node D:\\hooks\\notify.mjs" }]
} }
```

| 이벤트 | 때 | 막을 수 있나 |
|---|---|---|
| SessionStart | 대화의 첫 요청 | 아니오 |
| UserPromptSubmit | 요청을 받은 직후 | 예 |
| PreToolUse | 도구 쓰기 직전 (정책 검사 뒤, 승인 창 앞) | 예 |
| PostToolUse | 도구를 쓴 직후 | 아니오 (stdout이 모델이 보는 결과에 붙음) |
| Stop | 요청 하나가 끝났을 때 | 아니오 |

- 명령은 표준입력으로 JSON(`event, tool_name, tool_input, tool_response, prompt, status …`)을 받습니다.
- **종료 코드 2 = 막기**(이유는 stderr). 0 = 통과. stdout이 `{"decision":"block","reason":"…"}`여도 막습니다.
- 훅이 고장 나면(다른 종료 코드·10초 초과·실행 실패) **막지 않고 알리기만** 합니다.
- 대화에서: `hooks`(목록) · `hooks remove 2` · `hooks test` · 말로 "엑셀 저장 전에 기록 남기는 훅 만들어줘" (모델이 만든 명령은 **보여 주고 사람이 확인해야** 저장).
- 훅은 이 PC의 권한으로 돕니다. 팀 저장소에서 받은 훅은 읽지 않습니다.

### 시나리오 7. 계획 먼저 보기 + /명령 — **새 기능**

- `계획: MES에서 7라인 재공 내려받아 엑셀로 정리` → 3~7단계 계획이 보이고, 확인하면 그 계획대로 실행. 저장·상신 단계는 "(확인 필요)"로 표시.
- `/wip-check 7라인`, `/wip-check line=7라인`, `/memory`, `/new`, `/skills`, `/hooks`
- 여러 시스템에 걸치는 큰 일일 때 먼저 계획을 보고 싶을 때 씁니다.

### 시나리오 8. Excel·Word·PowerPoint 문서 다루기 (NASCA·EDM)

- **Excel:** 열린 문서 읽기·쓰기·저장 (`dogent excel docs`). EDM의 "읽기·편집"으로 Excel이 연 문서는 `excel_attach`로 잡아 읽고 그 자리에 저장.
- **Word/PPT:** `word_read/write/save`, `ppt_read/write/save`. 문단·표·슬라이드 글·발표자 메모 읽기, 찾아 바꾸기, 덧붙이기. **쓰기는 R3 + 사용자 허락.**
- NASCA 재암호화가 필요하면 `dogent config saveThroughExcel true`.
- 사용자의 문서는 닫지 않고 놓기만 하며, 다른 이름 저장은 사본만 만듭니다.

### 시나리오 9. Claude Code·opencode와 함께 쓰기

| 방향 | 방법 | 쓸 때 |
|---|---|---|
| Claude Code → 브라우저 (동작 단위) | `claude mcp add dogent -- node bridge/hub.mjs` | 스킬 없는 화면을 한 단계씩 직접 조작 |
| Claude Code·opencode → Dogent (일 단위) | 앱 MCP `http://127.0.0.1:39218/mcp` 또는 `dogent serve` | 큰 일을 계획하고 사내 웹 부분만 맡김 (`dogent_request`) |
| Dogent → Claude Code·opencode | `dogent agents add claude` / `opencode` | 표 분석·코드·파일 정리를 위임 (부를 때마다 사용자에게 묻기) |

예: "MES에서 7라인 재공 내려받아 클로드코드로 공정별 분석" → Dogent가 화면에서 내려받고 `claude.ask`로 분석을 위임.
Dogent는 한 번에 한 일만 받습니다(다른 일을 하는 중이면 "끝난 뒤에 다시").

### 시나리오 10. 정기 실행 (예약)

- `dogent schedule` — Windows 작업 스케줄러에 등록. **저장·상신은 하지 않는** 조회·리포트용.
- 예약 실행의 실제 동작은 사내에서 확인하지 못했고, 앱 화면은 아직 없습니다 (CLI만).

### 시나리오 11. 운영자: 문제 스킬 즉시 멈추기 (Hub)

- 화면이 바뀌어 스킬이 오작동하면 관리자가 중지 스위치를 겁니다.

```bash
curl -X POST $HUB/v1/admin/killswitch -H "Authorization: Bearer $HUB_ADMIN_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"scope":"skill","target":"gsams-request","reason":"화면이 바뀌어 깨짐"}'
```

- 클라이언트는 정책을 ETag로 주기적으로 받아 해당 스킬 실행을 막습니다. `scope`는 skill / system / all.

### 시나리오 12. 스킬 작성자: 만들기 → 검토 → 배포

1. 화면 점검으로 읽을 수 있는 화면인지 확인
2. 말로 만들기 또는 녹화 → 흐름 편집기에서 단계 카드 편집 → "▶ 여기까지 시험 실행"
3. `dogent check <SKILL.md>` 등급 B 이상
4. 시험 실행 20회 (성공률 90%, 값 일치 100%, 쓰기는 승인 없는 제출 0건)
5. 팀 저장소 PR → CI → CODEOWNERS 승인 → `index.json` 갱신 → 사용자 PC에 1시간 안에 반영

## 3. 상황별 빠른 표

| 하고 싶은 것 | 명령/말 |
|---|---|
| 스킬 목록·검색 | `dogent skills`, `dogent skills search 홀드 해제` |
| 스킬 정보·성공률 | `dogent skills info <id>` |
| 안 붙을 때 점검 | `dogent doctor [--fix]` |
| 열린 Excel 문서 | `dogent excel docs` |
| 지침 기억시키기 | "기억해: 결과 엑셀은 항상 D:\보고서에 저장" (`DOGENT.md`) |
| MCP 서버 연결 확인 | `dogent mcp list`, `dogent mcp test <이름>` |
| 훅 확인 | `hooks`, `hooks test` |
| 시험 실행 | `--dry-run` |
| 지금 팀 스킬·사전 받기 | `dogent sync` |

## 4. 하지 않는 것 (지금 범위 밖)

- 로그인·비밀번호 입력 (사람이 합니다)
- 승인 창 없는 저장·상신
- 화면에 없는 값을 추측해 입력
- 팀 저장소에서 받은 훅 자동 실행
- 구형 엑셀(xls) 내려받기 읽기 ([27](27-gaps-and-improvements.md) F3)
