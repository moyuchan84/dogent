## 1. 결정 요약

| # | 결정 | 이유 |
|---|---|---|
| D1 | **Claude Code + Claude in Chrome과 같은 구조로 나눈다.** 판단·스킬·모델 호출은 클라이언트가, 브라우저 조작은 확장이 맡는다 | 업무는 브라우저 밖(엑셀 문서, PC 파일, 예약 실행)에도 걸쳐 있다. 확장 하나에 모두 넣으면 문서 보안(NASCA) 파일을 다룰 수 없고 예약 실행도 어렵다 |
| D2 | **둘 사이는 MCP로 잇는다.** 확장의 화면 조작을 MCP 도구로 내놓는다 | 도구를 붙이는 방식이 하나로 정해진다. 나중에 한글(HWP), 사내 시스템 API 같은 도구도 같은 방식으로 더한다. 집에서는 Claude Code에 붙여 바로 시험할 수 있다 |
| D3 | **연결 방식은 Native Messaging과 localhost WebSocket을 둘 다 지원한다** | 회사 크롬 정책이나 보안 검토에서 어느 한쪽이 막혀도 다른 쪽으로 쓸 수 있다 |
| D4 | **클라이언트는 TypeScript(Node)로 만든다.** 처음은 터미널 프로그램이고, 화면은 나중에 Electron으로 입힌다 | 지금의 `src/core`(에이전트 루프, 스킬, 검사, 정책, 엑셀 가공)와 테스트를 그대로 쓴다. 다른 언어로 다시 쓰는 비용이 크다 |
| D5 | **문서 보안(NASCA) 파일은 C# 오피스 도구(`dogent-office.exe`)가 Excel을 COM으로 열어 다룬다** | NASCA 파일은 라이브러리로 직접 열 수 없고, 권한 있는 사용자의 Excel이 열어야 한다. COM 방식은 VSTO로 이미 동작을 확인했다. .NET Framework 4.8은 윈도우에 기본으로 있어 런타임을 설치하지 않아도 된다 |
| D6 | **안전장치는 확장에 둔다.** 조작할 사이트 목록과 저장·상신 승인은 어떤 클라이언트가 붙어도 확장이 직접 지킨다 | 외부 프로그램(Claude Code 포함)이 붙어도 같은 통제를 받아야 한다. 클라이언트를 믿을 필요가 없게 한다 |
| D7 | **스킬은 클라이언트의 스킬 폴더에 둔다(Claude Code 스킬처럼).** 단계는 목표 수준으로 적을 수 있고 매개변수는 실행마다 바뀐다. 녹화한 클릭 경로는 "빠른 경로"로 덧붙는다 | 업무를 아는 사람이 큰 흐름을 정하고, 화면 상황과 값은 에이전트가 맞춘다. 순수 녹화(RPA) 방식은 화면이나 값이 조금만 달라도 깨진다 |
| D8 | **스킬은 세 군데서 가져온다: 개인 폴더, 팀 공유 저장소(사내 GitHub Enterprise), 기본 제공.** 같은 id는 개인 > 팀 > 기본 순서로 앞의 것을 쓴다 | Claude Code(개인 스킬 / 플러그인 마켓플레이스 / 기본)와 같은 구조라 익숙하고, 별도 서버 없이 Git으로 검토 이력이 남는다 |
| D9 | **로그인은 사람이 한다.** 에이전트는 비밀번호를 입력하지 않는다. 로그인 화면을 만나면 멈추고 사용자에게 알린 뒤, 로그인이 끝나 화면이 바뀌면 그 자리에서 이어 간다 | 사내 시스템은 대부분 로그인(SSO)이 필요하다. 비밀번호를 스킬이나 에이전트가 다루면 보안 사고가 된다. Claude in Chrome도 같은 방식이다 |

### 바뀌는 설계 원칙

03 문서의 원칙 2 "흐름은 스킬이 쥔다. 모델이 자유롭게 계획하지 않는다"를 다음과 같이 고친다.

- 단계의 **순서와 끝났는지의 판정**은 여전히 스킬(검사 식)이 쥔다.
- 단계 **안에서** 무엇을 누를지는 모델이 화면을 보고 정할 수 있다. 목표만 적힌 단계가 그렇다.
- 도구와 인자가 적힌 단계와 기억한 경로는 지금처럼 모델 없이 실행한다.

## 2. 구성

```
┌──────────────────────────────────────────────┐
│ Dogent 클라이언트 (TypeScript / Node)            │
│  대화 · 에이전트 루프(src/core) · 스킬 폴더          │
│  Gemma 호출 · 승인 · 실행 기록 · 예약 실행(이후)     │
│  MCP 클라이언트                                   │
└───────┬───────────────────────────┬──────────┘
        │ MCP (stdio)               │ MCP (stdio)
┌───────▼────────────┐      ┌───────▼─────────────────┐
│ dogent 브리지         │      │ dogent-office.exe (C#)   │
│ bridge/hub.mjs      │      │ Excel COM: 열기·읽기·쓰기·저장 │
└───┬─────────────┬──┘      │ NASCA 문서                 │
    │ 파이프        │ WebSocket └─────────────────────────┘
┌───▼─────────┐   │ ws://127.0.0.1 (토큰 상호 인증)
│ native host  │   │
│ (크롬이 띄움) │   │
└───┬─────────┘   │
    │ Native Messaging
┌───▼──────────────▼──────────────────────────┐
│ Dogent 크롬 확장                                │
│  백그라운드: 도구 실행 (ChromeBrowser)            │
│  페이지 에이전트: 화면 읽기·조작 (src/page)         │
│  안전장치: 조작할 사이트, 저장·상신 승인 창           │
│  사이드 패널: 지금처럼 단독 실행도 가능 (이행 기간)    │
└──────────────────────────────────────────────┘
```

### 역할

| 구성 요소 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 클라이언트 | 요청 해석, 스킬 고르기, 단계 진행과 판단, 모델 호출, 데이터셋·가공, 결과 저장, 기록 | 화면을 직접 읽거나 누르지 않는다 |
| 브리지 | MCP 요청을 확장에 전하고 답을 돌려준다. 두 연결 방식을 한곳에서 받는다 | 판단하지 않는다. 상태를 갖지 않는다 |
| native host | 크롬과 브리지 사이의 중계 (크롬의 4바이트 길이 + JSON ↔ 파이프) | 그 밖에 아무것도 하지 않는다 |
| 확장 | 브라우저 도구 실행, 안전장치, 조작 중 표시 | 모델을 부르지 않는다 (사이드 패널 단독 실행은 이행 기간에만 둔다) |
| 오피스 도구 | Excel을 COM으로 다룬다 (열기, 시트·범위 읽기·쓰기, 저장, 닫기) | 판단하지 않는다 |

## 3. 브라우저 도구 (MCP)

확장이 내놓는 도구. 이름과 인자는 지금 스킬의 도구와 맞춘다.

| 도구 | 인자 | 결과 |
|---|---|---|
| `tabs_list` | | 조작할 수 있는 탭 목록 (id, 주소, 제목) |
| `tab_open` | `url` | 새 탭을 열고 대상으로 정한다 |
| `tab_select` | `tab_id` | 대상 탭을 바꾼다 |
| `snapshot` | `tab_id?` | 화면을 요소 번호가 붙은 텍스트로 |
| `navigate` | `url` | 이동. 조작할 사이트 밖이면 거절 |
| `click` | `ref`, `accept_dialog?` | 저장·상신 계열이면 확장의 승인 창을 거친다 |
| `type` / `select` | `ref`, `text` / `value` | |
| `wait_for` | `text`, `timeout_sec?` | |
| `extract_table` | `ref`, `next_ref?` | 컬럼과 행 (페이지 넘김 포함) |
| `download_table` | `ref` | 내려받은 파일을 표로 |
| `fill_table` | `ref`, `columns`, `rows`, `add_ref?` | 넣은 뒤 화면 값을 다시 읽어 대조 |
| `read_text` | `ref?` | 화면(또는 영역)의 글. 요약은 클라이언트가 한다 |
| `inspect` | | 화면 점검 결과 |

- ref는 마지막 `snapshot` 기준이다. 같은 탭에서는 다음 `snapshot`까지 유지된다.
- 화면의 알림·확인 창은 띄우지 않고 내용을 결과에 붙인다 (지금 방식 그대로).

## 4. 연결과 인증

| | Native Messaging | localhost WebSocket |
|---|---|---|
| 연결 | 확장이 `connectNative("com.dogent.bridge")` → 크롬이 native host를 띄움 → native host가 브리지의 파이프(`\\.\pipe\dogent-bridge`)에 붙음 | 브리지가 `127.0.0.1:<포트>`에서 기다리고 확장이 붙음 |
| 설치 | `pnpm bridge:install`: 호스트 매니페스트 파일과 레지스트리(HKCU, 관리자 권한 불필요)를 등록 | 없음 |
| 누가 붙을 수 있나 | 크롬이 매니페스트의 `allowed_origins`(확장 ID)만 허용 | 웹페이지도 localhost에 접속할 수 있으므로 토큰으로 서로 확인 |
| 인증 | 파이프에서도 같은 토큰을 확인 | 양쪽이 서로의 난수에 HMAC-SHA256(토큰)으로 답해야 연결 |
| 막힐 수 있는 곳 | 크롬 정책 `NativeMessagingBlocklist`/`Allowlist` | 보안 프로그램이 로컬 포트를 막는 경우 |

- 토큰은 브리지가 처음 실행될 때 사용자 폴더(`~/.dogent/bridge-token`)에 만든다. 확장의 설정 → 클라이언트 연결에 붙여 넣는다.
- 확장 ID는 매니페스트의 `key`로 고정한다. 압축해제 설치라도 PC마다 ID가 같아야 native host 매니페스트에 적을 수 있다.

## 5. 스킬 저장소 (D8)

| 출처 | 위치 | 들어가는 것 |
|---|---|---|
| 개인 | `%USERPROFILE%.dogentskills<id>SKILL.md` | 녹화·자유 요청으로 만든 것, 받은 zip. 품질 검사와 시험 실행을 거쳐 들어간다 |
| 팀 | 사내 GitHub Enterprise의 `dogent-skills` 저장소 (틀: `templates/dogent-skills`) | PR로 올리고, CI(품질 검사 B 이상, 목록 확인)와 CODEOWNERS 승인을 거친 스킬 |
| 기본 | 클라이언트·확장에 들어 있는 것 (`skills/`) | 예제와 공통 스킬 |

- 팀 저장소는 평범한 Git 저장소다. 스킬 하나가 폴더 하나(`<id>/SKILL.md`, 선택으로 `policy.yaml`)이고, `skills/index.json`에 해시와 함께 목록을 둔다.
- 확장은 지금도 이 목록 주소(`WXT_SKILLS_URL`)로 받아 쓴다. 비공개 저장소는 "브라우저 로그인으로 읽기"(`WXT_SKILLS_WITH_LOGIN`)로 브라우저의 사내 GitHub 세션을 써서 읽는다.
- 클라이언트로 옮긴 뒤에는 같은 저장소를 사용자의 Git 자격 증명으로 받아(`git pull`) 쓴다. 저장소 구조는 바뀌지 않는다.
- CI 검사기(`tools/skill-check.mjs`)는 Dogent의 검사 규칙을 한 파일로 묶은 것이다(`pnpm skill:bundle`). 사내 러너에 Node만 있으면 된다.

## 6. 로그인 처리 (D9)

> 확장 단독 버전에 구현됨 (사이드 패널 실행, 최대 5분 대기). 브라우저 도구(MCP)의 `wait_for_login`은 1단계에서 같은 규칙으로 붙인다.

| 상황 | 동작 |
|---|---|
| 실행 중 비밀번호 칸이 있는 화면을 만남 | 실행을 멈추고 "이 탭에서 로그인해 주세요"를 알린다. 화면은 그대로 둔다 |
| 사용자가 로그인함 (SSO 자동 로그인 포함) | 비밀번호 칸이 사라지면 그 단계부터 이어 간다. 로그인 뒤 다른 화면으로 갔으면 단계의 검사와 모델이 다시 맞춘다 |
| 제한 시간(기본 5분) 안에 로그인하지 않음, 또는 사용자가 중지 | 실행을 끝내고 "로그인이 필요합니다"로 기록한다 |
| 브라우저 도구(MCP) | `snapshot` 결과에 로그인 화면이라는 표시를 붙이고, `wait_for_login` 도구로 로그인이 끝나기를 기다린다. 어떤 클라이언트가 붙어도 비밀번호 칸에는 입력하지 않는다 |

## 7. 지금 코드의 이동

| 지금 | 이후 |
|---|---|
| `src/core/*` | 클라이언트로 옮긴다. 확장에서는 이행 기간 동안 사이드 패널이 함께 쓴다 |
| `src/page/*` | 확장에 남는다 |
| `src/ext/browser.ts` (ChromeBrowser) | 확장 백그라운드에서 도구를 실행하는 데 쓴다 |
| `BrowserPort` (core/types.ts) | 클라이언트 쪽에 MCP로 구현한 `McpBrowser`가 생긴다. 루프 코드는 바뀌지 않는다 |
| `skills/` | 클라이언트의 스킬 폴더 형식으로 옮긴다. 공유 스킬 저장소도 클라이언트가 읽는다 |
| `src/core/excel.ts`의 엑셀 저장 | NASCA 규정에 따라 오피스 도구로 저장하도록 바꿀 수 있게 한다 (확인 필요, 7절) |

## 8. 진행 순서

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 1 | 확장을 브라우저 도구 서버로 만들기. 브리지, native host, 두 연결 방식, 승인 창 | Claude Code에 브리지를 MCP로 붙여 모의 사이트에서 재공 조회를 끝까지 할 수 있다. 저장·상신은 승인 창을 거친다 |
| 2 | 터미널용 Dogent 클라이언트. Gemma, 스킬 폴더, `McpBrowser`. 목표 단계, 화면 요약, 잘 된 실행을 스킬로 만들기 | 지금 e2e 시나리오가 클라이언트 + 확장 구성으로 통과한다 |
| 3 | `dogent-office.exe`. Excel COM 도구 | NASCA 문서를 열어 표를 읽고, 결과를 Excel로 저장한다 |
| 4 | 데스크탑 화면(Electron). 사이드 패널은 승인·진행 표시용으로 줄인다 | 현업 사용자가 터미널 없이 쓴다 |

## 9. 확인할 것

| 항목 | 확인 방법 | 영향 |
|---|---|---|
| Excel로 저장한 파일이 NASCA로 다시 암호화되는지 | VSTO나 PowerShell COM으로 저장해 본다 | 암호화되어야 하면 결과 엑셀은 오피스 도구로 저장한다 (지금 확장은 암호화되지 않은 파일을 만든다) |
| 회사 크롬의 Native Messaging 정책 | `chrome://policy`에서 NativeMessaging 항목 확인 | 막혀 있으면 WebSocket으로 쓴다 |
| 로컬 포트 사용 가능 여부 | 브리지를 띄우고 확장이 붙는지 본다 | 막혀 있으면 Native Messaging으로 쓴다 |
| 확장 설치 방식 | 압축해제 설치가 막히면 사내 배포(정책 설치) 필요 | 확장 ID 고정과 함께 정한다 |
| 사내 GitHub 원본 파일 주소 | 팀 저장소의 `raw/main/skills/index.json`을 브라우저에서 열어 본다. 다른 호스트로 넘어가는지 확인 | 넘어가면 그 호스트도 조작할 사이트에 더한다 |
| 사내 러너 | 팀 저장소에 Actions 러너(self-hosted)와 라벨이 있는지 | 없으면 CI 대신 PR 전에 `node tools/skill-check.mjs`를 손으로 돌린다 |
