Dogent 도입 흐름

사내 PC에 설치해서 써 보고, 엔지니어가 새 스킬을 만들어 실행하고, 그 스킬을 공유·적용·자동화하기까지. 지금 만들어진 것으로 되는 부분과 아직 안 되는 부분을 나눠 적었습니다.

기준: 2026-10-14, Phase 2 진행 중 (크롬 확장 단독 구성) · 상세는 README.md, docs/04-roadmap.md, docs/06-skill-authoring.md

지금 되는 것. 확장을 직접 빌드해 개발자 모드로 설치하면, 사내 PC에서 스킬 실행과 스킬 만들기(녹화 → 품질 검사 → 시험 실행)까지 해 볼 수 있습니다.

지금 손으로 해야 하는 것. 설치, 대상 시스템 주소 등록, 스킬 공유는 모두 "설정 파일 수정 → 다시 빌드 → 확장 다시 로드"를 거칩니다. 만든 스킬을 다른 사람이 쓰려면 스킬 파일을 저장소에 넣고 확장을 다시 만들어 나눠야 합니다.

아직 없는 것. 정책 배포에 의한 자동 설치, 확장을 다시 깔지 않는 스킬 동기화, 스케줄 실행(자동화), 중앙 관리(Hub)는 Phase 2 후반~Phase 3 계획입니다.

단계별로 본 지금과 최종

왼쪽이 오늘 저장소에 있는 것으로 할 수 있는 방법, 오른쪽이 로드맵대로 다 만들어졌을 때의 모습입니다.

소스를 빌드한 폴더(.output/chrome-mv3)를 chrome://extensions에서 개발자 모드로 로드합니다. PC마다 직접 해야 합니다.

Phase 2 후반

사내 인증서로 서명한 확장을 사내 파일 서버에 올리고, 브라우저 정책으로 자동 설치·자동 업데이트합니다. 사용자는 아무것도 하지 않습니다.

모델·시스템 연결
수동

빌드하는 PC의 .env.local에 Gemma API 주소와 공용 키를, dogent.config.ts에 대상 시스템 주소를 적고 빌드합니다. 사용자는 설정을 입력하지 않습니다.

사내 Gemma로는 아직 돌려 보지 않았습니다. OpenAI 호환 /chat/completions 형식을 가정합니다.

Phase 3

허용 도메인, 모델 주소, 금지 동작을 운영자가 Hub에서 정책으로 내려보냅니다. 공용 키는 확장에 넣지 않고 Hub가 모델 호출에 대신 붙여, 사용자별 사용량을 구분하고 키를 바꿀 때 재배포하지 않습니다.

스킬 실행
됨

패널에서 스킬을 골라 입력값을 넣고 실행합니다. 말로 요청하면 맞는 스킬과 입력값을 찾아 줍니다. 스킬이 없으면 "자유 요청"으로 현재 화면을 조작합니다.

저장·상신은 사용자 승인을 받아야 누르고, "시험 실행"은 그 직전에 멈춥니다.

Phase 3

같은 방식에 더해, 데스크탑 클라이언트가 PC의 폴더와 엑셀 양식을 다루고 여러 시스템을 묶은 리포트를 만듭니다.

스킬 만들기
됨

패널의 "스킬 만들기"에서 업무를 한 번 해 보이면 절차서 초안이 나옵니다. 품질 검사(등급 A~F)와 시험 실행을 통과하면 배포를 요청할 수 있습니다.

초안은 만든 PC에서만 보이고 실행됩니다.

Phase 3

녹화로 만든 초안을 사람이 손대는 일을 더 줄입니다. (새 창, 표의 행, 알림·확인 창, 표 페이지 넘김, 엑셀로 표 채우기는 지금도 녹화되고, 초안의 글은 모델로 다듬을 수 있습니다.)

공유·적용
됨

초안의 SKILL.md를 내려받아 스킬 저장소의 skills/<id>/에 넣고 검토를 받습니다. 병합된 뒤 pnpm skill:index로 목록을 만들어 사내 파일 서버나 Git에 올리면, 각 PC의 확장이 패널을 열 때 받아 와 [공유]로 보여줍니다. 확장을 다시 배포하지 않습니다.

저장소 주소는 빌드할 때 .env.local의 WXT_SKILLS_URL에 적습니다. 새 시스템(허용 목록에 없는 주소)을 다루는 스킬만 확장을 다시 빌드해야 합니다.

Phase 3

Hub가 부서·사용자별로 쓸 수 있는 스킬을 정하고, 허용 주소도 정책으로 내려보내 새 시스템을 다루는 스킬도 재배포 없이 적용합니다.

자동화
없음

사람이 패널에서 실행을 눌러야 합니다. 스킬에 schedulable 선언은 있지만 정해진 시각에 돌리는 기능은 없습니다.

Phase 3

데스크탑 클라이언트의 스케줄러가 조회·내려받기 스킬(R0~R1)을 정해진 시각에 돌립니다. 저장·상신이 있는 스킬(R3)은 사람의 승인이 필요하므로 무인으로 돌리지 않습니다.

운영
수동

실행 기록은 각 PC에 남습니다(최근 50건). 패널의 "기록" 탭에서 지난 실행을 다시 열어 보고 스킬별 성공률을 봅니다. 전에는 되던 스킬이 연달아 실패하면 표시하지만, 그 PC에서 실패해 봐야 알 수 있고 담당 부서에는 사람이 알려야 합니다.

Phase 3~4

Hub가 기록을 모아 스킬별 실행 횟수·성공률을 보여주고, 성공률이 떨어지면 화면이 바뀐 것으로 보고 스킬 담당 부서에 알립니다. 문제가 생기면 중앙에서 멈춥니다.

됨 지금 그대로 쓸 수 있음 수동 되지만 사람이 빌드·파일 복사를 해야 함 계획 아직 만들지 않음

지금 사내 PC에서 해 보는 순서

개발자 한 명이 빌드해서 폴더를 건네면, 엔지니어는 3번부터 하면 됩니다.

  1. 먼저 확인할 것 개발 · 보안

    • 사내 PC의 Chrome에서 개발자 모드로 확장을 로드할 수 있는지. 정책으로 막혀 있으면 이 방법은 쓸 수 없고, 서명·정책 배포가 먼저 필요합니다.
    • 확장이 쓰는 권한: sidePanel, scripting, storage, tabs, downloads, 그리고 대상 시스템과 모델 API 주소에 대한 접근.
    • 사내망에서 pnpm install이 되는지 (사내 npm 저장소). 안 되면 밖에서 빌드한 .output/chrome-mv3 폴더나 pnpm zip으로 만든 압축 파일을 반입합니다.
    • 사내 Gemma API의 주소·키와 형식 (OpenAI 호환 /chat/completions인지). 다르면 src/core/llm.ts를 고쳐야 합니다.

  2. 공용 키와 대상 주소를 넣고 빌드 개발

    Gemma API의 공용 키는 저장소가 아니라 빌드하는 PC의 .env.local에 적습니다. 이 파일은 Git에 올라가지 않고, 빌드할 때 확장 안에 들어갑니다. 조작할 시스템의 주소는 dogent.config.ts에 적습니다. 여기 없는 사이트는 스킬에 적어도 동작하지 않습니다.

    cp .env.example .env.local       // 복사한 뒤 값을 채움
  WXT_LLM_BASE_URL=https://gemma.example.internal/v1
  WXT_LLM_API_KEY=(공용 키)
  WXT_LLM_MODEL=(모델 이름)

// dogent.config.ts
sitePermissions: ['https://mes.example.internal/*'],   // 조작할 사내 시스템

pnpm install
pnpm build        // .output/chrome-mv3 폴더가 만들어짐
pnpm zip          // 나눠 줄 압축 파일

    공용 키는 확장 파일 안에 글자 그대로 들어가므로, 빌드 결과물은 사내에서만 나누고 저장소에는 올리지 않습니다.

  3. 확장 설치 엔지니어

    chrome://extensions → 개발자 모드 켜기 → "압축해제된 확장 프로그램을 로드합니다" → 받은 폴더 선택. 툴바의 Dogent 아이콘을 누르면 오른쪽에 패널이 열립니다.

    지금까지는 Chromium으로만 시험했습니다. Edge는 따로 확인이 필요합니다.

  4. 모델 연결 엔지니어

    공용 키를 넣어 빌드한 확장이면 할 일이 없습니다. 설치하면 바로 모델에 연결되고, 키는 설정 화면에 보이지 않습니다. 키 없이 빌드한 확장이면 패널 → 설정에서 API 주소, 모델 이름, API 키를 넣습니다.

    번들된 스킬과 녹화로 만든 스킬은 단계마다 누를 요소와 값이 적혀 있어 대부분 모델 없이 돕니다. 모델은 말로 한 요청을 해석할 때, 자유 요청, 그리고 화면이 달라져 적힌 대로 안 될 때 쓰입니다.

  5. 화면이 읽히는지 확인 엔지니어

    업무 화면을 열고 로그인한 뒤, 스킬 목록에서 "자유 요청"을 골라 "이 화면에서 조회 버튼을 눌러줘"처럼 시켜 봅니다. 화면에 파란 테두리가 뜨고 요소가 가리켜지면 그 시스템을 읽고 조작할 수 있는 것입니다.

    로그인 화면에서는 일부러 멈춥니다. 비밀번호는 읽지도 입력하지도 않습니다.

  6. 스킬을 만들어 실행 엔지니어

    아래 "새 스킬을 만드는 흐름"대로 녹화 → 검사 → 초안 저장 → 시험 실행을 합니다. 여기까지는 다시 빌드하지 않고 그 PC에서 바로 됩니다.

  7. 다른 사람과 공유 엔지니어 → 검토자 → 개발

    "내 초안"에서 SKILL.md를 내려받아 저장소의 skills/<id>/SKILL.md로 올리고 검토를 받습니다. 병합 후 개발자가 다시 빌드한 폴더를 나누면 모두의 스킬 목록에 나타납니다.

    pnpm skill:lint   // 저장소의 스킬 전체를 같은 규칙으로 검사 (전부 A등급이어야 통과)
pnpm build

실제 화면에서 되는 것과 안 되는 것

모의 사이트로 검증한 범위입니다. 실제 사내 시스템에서는 Phase 0의 화면 구조 조사로 확인해야 합니다.

화면의 구성상태비고
표준 HTML의 입력란·선택 상자·버튼·링크됨라벨이나 버튼 글자로 요소를 찾습니다
iframe 안의 업무 화면됨포털 안에 들어 있는 화면
HTML 표 읽기, 페이지 넘기며 전부 추출됨추출한 행 수를 화면의 총 건수와 대조
엑셀·CSV 내려받기 버튼으로 받은 파일 읽기됨xlsx, csv. 구형 xls는 안 됨
엑셀 파일을 화면의 입력 표에 일괄 입력됨입력 후와 저장 전에 화면 값을 원본과 대조
팝업 창에서 값 고르기, 알림·확인 창됨확인 창은 기본 취소. 저장·상신을 묻는 창은 승인받은 제출에서만 확인
표 안의 링크·버튼·입력란을 행을 가려 조작됨행마다 같은 버튼이 있으면 그 행의 글자로 가립니다. 표 하나에 60개까지
전용 그리드(화면에 보이는 행만 그리는 방식), 캔버스로 그린 화면안 됨내려받기 버튼이 있으면 그쪽을 쓰고, 없으면 시스템별 처리기를 따로 만들어야 합니다
IE 전용, ActiveX, 설치형 프로그램범위 밖

새 스킬을 만드는 흐름

엔지니어가 형식을 외우지 않고 만들 수 있게, 초안의 모양과 품질 기준을 도구가 정합니다. 1~4는 지금 패널에서 됩니다.

  1. 녹화 됨

    업무의 첫 화면을 열고, 패널 → 스킬 만들기에서 스킬 ID·이름·설명·담당 부서를 적은 뒤 "녹화 시작". 평소대로 업무를 한 번 합니다. 표를 엑셀로 내려야 하면 "화면의 표 읽기 추가"를 누르거나 화면의 엑셀 내려받기 버튼을 누릅니다. 엑셀 파일을 화면의 입력 표에 넣는 업무면 "엑셀로 표 채우기 추가"를 누르고 표를 고릅니다.

  2. 입력받을 값 고르기 됨

    녹화된 조작마다 "실행할 때마다 입력받기"를 켜면 스킬의 입력 항목이 되고(라인, IP, 사유 등), 끄면 녹화한 값으로 고정됩니다. 실수로 누른 것은 뺍니다.

  3. 품질 검사 됨

    초안에 등급과 지적 사항이 붙습니다. 오류가 있으면(F) 저장할 수 없고, 배포를 요청하려면 B 이상이어야 합니다. 저장·상신 버튼을 눌렀으면 승인 통제가 자동으로 선언됩니다.

    "모델로 다듬기"를 누르면 스킬 설명, 입력 이름, 단계 설명, 예외 문구를 모델이 제안합니다. 누를 요소와 값, 검사 식, 승인 통제는 모델이 바꿀 수 없고, 바뀌는 제안은 넣지 않습니다.

  4. 시험 실행 됨

    "초안으로 저장"하면 실행 탭의 목록에 [초안]으로 나타납니다. 녹화할 때와 다른 값으로 돌려 봅니다. 저장·상신이 있으면 "시험 실행"을 켜서 제출 직전에 멈추게 합니다. 내용을 고치면 다시 돌려야 합니다.

  5. 배포 요청과 검토 수동

    SKILL.md를 내려받아 저장소에 올립니다. 검토자는 도구가 판단할 수 없는 것만 봅니다: 자동화해도 되는 업무인지, 고정한 값이 맞는지, 넣으면 안 되는 값의 규칙(policy.yaml)이 충분한지.

    검토자는 받은 SKILL.md를 패널의 "내 초안"에서 가져와 자기 PC에서 바로 검사하고 시험 실행해 볼 수 있습니다.

  6. 적용 됨

    병합 후 스킬 저장소에서 pnpm skill:index로 목록을 다시 만들어 사내 파일 서버나 Git에 올립니다. 각 PC의 확장이 패널을 열 때 받아 와 목록에 [공유]로 보여줍니다. 확장을 다시 빌드하는 것은 새 시스템의 주소를 허용 목록에 더할 때뿐입니다.

자동화의 범위

  • 사용자 PC와 그 사람의 로그인 세션 안에서만 돕니다. 서버에서 사람 없이 도는 완전 자동화는 범위 밖입니다.
  • 저장·상신·삭제가 들어가는 스킬은 스케줄로 돌려도 승인 화면에서 사람을 기다립니다. 결재를 대신하지 않습니다.
  • 로그인이 풀려 있으면 중단하고 알립니다. 계정이나 비밀번호를 저장해 다시 로그인하지 않습니다.

PC마다 개발자 모드로 직접 설치확장 서명, 사내 파일 서버 게시, 브라우저 정책 설치Phase 2
새 시스템을 다루는 스킬은 확장을 다시 배포허용 주소를 Hub의 정책으로 배포, 부서별 스킬 사용 권한Phase 3
주소·모델 설정을 파일로 관리Hub의 정책 배포Phase 3

스킬이 깨져도 실패해 봐야 앎실행 기록 중앙 수집, 스킬별 성공률 모니터링Phase 3
