Dogent 사용 가이드와 개선 방향

2026-10-21 기준 · 브랜치 feature/tool-registry (마지막 커밋 589178f) · 코드를 직접 읽고 테스트를 돌려 확인한 내용으로 작성

0. 작성하던 기능은 구현이 끝났나?

결론: 코드는 동작하지만 "끝났다"고 하기엔 이릅니다. 이번 브랜치의 작업(MCP 커넥터, 도구 레지스트리, 서브에이전트 run_skill, 스킬 지연 로딩 1단계)은 구현되어 테스트를 통과하지만, 커밋되지 않은 채 쌓여 있고 (이 문서를 쓴 뒤 e2e 실패는 수정함) 설계 문서가 "아직"이라고 적은 부분이 남아 있습니다.

외부 도구 호출 call_tool (스킬 직접 단계로도 가능)구현됨src/core/external.ts, actions.ts

도구 묶음, skill_ref/refs/, delegate, lint의 id 존재·순환 검사미구현docs/13 §3~4가 "아직"으로 표기

e2e "MCP 서버" 시나리오실패§10-1 참조 (시스템 사전과 MCP 라우팅 충돌)

권장 순서: ① e2e 실패 1건 수정 → ② 변경을 의미 단위로 쪼개 커밋(docs/13 §4의 0단계) → ③ 사내 PC에서 "화면 점검" 보고서와 조회 1건 실행. 이 문서는 ①~③을 하지 않은 현재 상태 기준입니다.

1. 구조

Claude Code + Claude in Chrome 구조를 따라 판단은 클라이언트가, 화면 조작은 브라우저 확장이 맡고 둘은 MCP로 이어집니다. 엑셀(문서 보안 문서 포함)은 클라이언트가 오피스 도구로 직접 다룹니다.

클라이언트 (터미널 dogent.mjs / 데스크탑 Dogent.exe)에이전트 루프 · 스킬 · 사내 Gemma 호출 · 승인 · 실행 기록 · 예약
▼ 같은 프로세스 안
브리지Native Messaging / WebSocket(127.0.0.1:39217) → 크롬·엣지 확장 → 사내 웹
오피스 도구dogent-office.exe → Excel COM → NASCA 문서·EDM에서 연 문서
MCP 허브 (신규)~/.dogent/mcp.json의 서버들(stdio·원격) → 서버.도구 이름으로 모델에 노출
스킬 저장소개인 ~/.dogent/skills > 팀(team-cache/git) > 기본(빌드 포함)
시스템 사전SYSTEM.md: 별칭·주소·화면 경로·용어
확장의 통제허용 사이트 · 저장/상신 승인 창 · 로그인은 사람이

핵심 원칙은 모델에게 맡기는 판단을 최소화하는 것입니다. 무엇을 누를지·단계가 끝났는지·제출해도 되는지를 스킬 문서와 규칙이 정하고, 모델은 절차가 어긋났을 때의 복구와 목표 단계에서만 쓰입니다. 코드는 세 곳에 나뉩니다.

위치역할
src/core/환경 의존이 없는 핵심: 루프(loop.ts), 프롬프트, 계획기, 스킬 파서·lint, 정책, 서브에이전트, 외부 도구
client/src/터미널 클라이언트: 세션, 스킬/시스템 로딩, MCP 허브, 브리지, 오피스, 예약, doctor
entrypoints/, desktop/크롬 확장(사이드 패널·서비스 워커), Electron 데스크탑 앱

3. 사용법

3-1. 빌드와 설치

pnpm install
pnpm build                  # 크롬 확장 → .output/chrome-mv3  (chrome://extensions 에서 "압축해제된 확장 프로그램" 로드)
pnpm client:build           # 터미널 클라이언트 → client/dist/dogent.mjs
pnpm desktop               # 데스크탑 앱 실행 (빌드 포함)

# 모드: dev(모의 모델) / home(.env.home.local, Ollama) / company(.env.company.local, 사내 Gemma)
pnpm client:build:company
install\build.cmd -Mode company -Zip     # 사용자 PC 배포 묶음 (install.cmd 하나로 설치)

집에서 시험하려면 pnpm mock:site(모의 사내 사이트 :4173)와 pnpm mock:llm(모의 모델 :4174) 또는 pnpm ollama:proxy를 띄웁니다.

3-2. 연결 확인

dogent browsers                 # 확장이 붙은 브라우저(크롬/엣지)
dogent doctor [--fix]           # 안 붙을 때: 토큰·포트·Native Messaging 등록·회사 정책 점검
dogent token                    # WebSocket 방식일 때 확장 설정에 넣을 토큰

3-3. 터미널 클라이언트 명령

명령설명
dogent대화 모드. 말로 일을 시키고 exit로 끝낸다
dogent "7라인 재공 확인해줘"요청 한 건. 맞는 스킬이 있으면 스킬로, 없으면 자유 요청
dogent run wip-check line=7라인스킬을 입력값과 함께 직접 실행. 파일 입력은 이름=경로
dogent skills [search 말 | info ID]스킬 목록·검색·상세(입력, 위험도, 담당, 성공률)
dogent skill new "업무 설명" / skill edit ID말로 스킬 만들기 / 편집 후 자동 품질 검사
dogent check SKILL.md스킬·시스템 문서 품질 검사
dogent sync팀 스킬 저장소 받기
dogent systems [info ID]시스템 사전 보기
dogent mcp …MCP 서버 관리 (§8)
dogent excel <파일|문서이름> | docs | resave엑셀 열기·열린 문서 목록·NASCA 재저장 확인
dogent schedule add 이름 --at 09:00 --days 월,수,금 스킬ID 이름=값예약 실행 (로그인한 동안만, 저장·상신은 하지 않음)
dogent config [키 값]설정 보기·변경 (예: llm.userId, browser edge, teamSkillsUrl)

공통 옵션: --yes(확인 생략) · --allow-write(자유 요청에서 저장·상신 허용, 누르기 전 승인 창) · --dry-run(상신 직전에 멈춤) · --browser edge · --wait 초

3-4. 데스크탑 앱

  • 대화: 요청 입력 → 스킬 선택/입력값 확인 → 실행. 저장·상신 승인 창, 시험 실행 토글, 중지 버튼.
  • 스킬 탭: 검색창, 맨 위 "지금 화면" 묶음, 말로 스킬 만들기. 시스템 탭: 사전 보기. 엑셀 탭: 열린 문서 보기.
  • 커넥터 탭(신규): MCP 서버 목록 → 펼치면 연결 시험과 도구별 권한 설정, "＋ 커넥터 추가"로 설치 명령 붙여넣기.
  • 왼쪽 목록 너비는 손잡이로 조절(방향키·더블클릭 지원).

3-5. 사이드 패널(확장)

툴바 아이콘 → 사이드 패널 → 스킬 선택(검색 가능한 SkillPicker) → 입력 → 실행. 설정에서 모델 주소·키·제한 시간 배율·공유 스킬 저장소 주소·클라이언트 연결(WebSocket/Native Messaging)을 바꿉니다. "화면 점검" 보고서로 사내 화면의 iframe·canvas·shadow DOM 호환성을 미리 수집할 수 있습니다.

2 팀~/.dogent/team-cache/ 또는 teamSkills(git clone 폴더)dogent sync (index.json 주소 = teamSkillsUrl, 해시·품질 검사 통과한 것만 받음)
3 기본클라이언트 빌드에 포함 (skills/)저장소에 추가 후 pnpm client:build

같은 id면 앞의 것이 이깁니다. 개인 스킬로 팀 스킬을 임시로 덮어써 시험할 수 있습니다.

6-2. 만드는 네 가지 방법

  1. 말로 만들기 — dogent skill new "재공 조회해서 엑셀로" 또는 앱 버튼. 지금 브라우저 화면을 보고 초안 → 말로 고치기 → 시험 실행 → 저장.
  2. 자유 요청을 저장 — 자유 요청이 성공하면 "스킬로 저장할까요?" (자식 스킬의 동작은 섞이지 않게 처리됨).
  3. 녹화 — 사이드 패널에서 조작을 녹화해 초안을 만든다 (표 페이지 넘김·일괄 입력 녹화는 미구현).
  4. 직접 작성 — pnpm skill:new로 뼈대를 만들고 SKILL.md를 편집, dogent check/pnpm skill:check로 검사.

6-3. SKILL.md 최소 예시

---
id: wip-check
name: 재공 확인
description: 라인·공정별 재공 현황을 조회하고 정체 Lot과 공정별 집계를 엑셀로 정리한다
version: 0.1.0
owner: 생산관리
risk: R1                  # R3가 아니면 저장·상신 버튼은 어느 단계에서도 누를 수 없다
domains: [localhost:4173] # 이 밖으로는 이동·조작 불가
tags: ["재공", "WIP", "정체 Lot"]
inputs:
  - name: line
    label: 라인
    type: string          # string|number|text|enum|ip|port|file
    required: true
    description: 조회할 라인 이름. 예 7라인
limits: { max_steps: 40, timeout_sec: 300 }
---

## 단계
1. navigate로 재공 현황 조회 화면으로 이동한다. args는 다음을 그대로 쓴다.
   `{"url": "http://localhost:4173/wip.html"}`
   - 확인: 화면에 "재공 현황 조회" 제목이 보인다.
   - 검사: text("재공 현황 조회")
2. select로 "라인"에서 {line}을 선택한다. args는 다음을 그대로 쓴다.
   `{"ref": "라인", "value": "{line}"}`
   - 검사: value("라인") == "{line}"
3. 결과 중 상태가 HOLD인 Lot의 사유를 확인한다.      ← 목표 단계: 모델이 화면을 보고 판단

## 예외
- 조회 결과가 0건이면 abort로 "결과 없음"을 보고한다.
## 결과
- 라인, 총 건수, 정체 Lot 건수를 보고한다.

6-4. 단계에 쓸 수 있는 것

종류쓰는 법
직접 단계"도구로" 로 시작 + 백틱 JSON 인자 → 모델 없이 실행. 도구: navigate·open_tab·click·close_tab·type·select·extract_table·download_table·fill_table·transform·write_excel·excel_*·call_tool·run_skill·read_text·summarize·finish
목표 단계할 일만 문장으로. 모델이 화면을 보고 동작을 고름. 중간 단계엔 - 검사: 권장 (없으면 lint W01)
자리표시자{입력이름} · {out.이름}(기록/요약 값) · {rows.데이터셋}(행 수)
저장·상신risk: R3 + submit_steps + (선택) submit_labels. 누르기 직전 승인 창
입력 규칙같은 폴더의 policy.yaml (예: 방화벽 신청의 IP/포트 규칙)

8. MCP·커넥터를 클라이언트에서 추가해 쓰는 법

Dogent는 두 방향으로 MCP를 씁니다. 헷갈리지 않게 구분하세요.

(A) Dogent가 MCP 클라이언트일 때 (이 절)(B) Dogent가 MCP 서버일 때 (§9)
방향Dogent → 사내 시스템의 MCP 서버Claude Code 등 → Dogent 브리지 → 브라우저 확장
목적화면 대신 API형 도구로 조회·처리외부 에이전트가 브라우저를 조작
설정~/.dogent/mcp.jsonclaude mcp add dogent -- node bridge/hub.mjs

8-1. 추가하는 방법 (모두 같은 mcp.json에 저장됨)

방법입력
데스크탑 → 커넥터 탭 → ＋ 커넥터 추가사내 마켓에서 복사한 글을 그대로 붙여넣기: claude mcp add … 명령, {"mcpServers":{…}} JSON, 또는 서버 주소(http://…/mcp). 더하기 전에 어디로 무엇이 전송되는지·이 PC에서 실행될 명령을 미리 보여 줌
CLI (원격)dogent mcp add github-mcp http://서버/mcp --transport http --header "Authorization: Bearer ${GH_TOKEN}"
CLI (이 PC에서 실행)dogent mcp add mes -e KEY=값 -- npx -y @회사/mes-mcp
CLI (JSON)dogent mcp add-json 이름 '{"type":"http","url":"http://서버/mcp"}' · dogent mcp import 파일|주소 (Claude Code·Cursor·VS Code·opencode 형식 모두 읽음)
파일 직접 편집~/.dogent/mcp.json (Claude Code 형식 mcpServers도 읽음)

더한 뒤에는 연결 시험을 자동으로 합니다(--no-test로 생략). 터미널이 아닌 자동 실행에서는 --yes 없이는 더하지 않습니다.

8-2. mcp.json 모양과 권한

{
  "servers": {
    "mes": {
      "url": "https://mes.example.net/mcp", "transport": "http",
      "headers": { "Authorization": "Bearer ${MES_TOKEN}" },   // ${…}는 이 PC의 환경 변수로 채움 → 토큰을 파일에 적지 않음
      "keywords": ["재공", "Lot"],                               // 요청에 나오면 브라우저 없이 이 서버로 처리
      "permissions": { "lot_list": "allow", "lot_hold": "ask", "*": "ask" }
    },
    "local-tool": { "command": "npx", "args": ["-y", "@회사/tool-mcp"], "env": { "KEY": "${KEY}" } }
  }
}
권한동작
allow묻지 않고 부름 (기본값: 서버가 readOnlyHint로 표시한 읽기 도구)
ask부르기 전에 사용자에게 묻고 부름 (기본값: 그 밖의 "바꾸는 도구")
deny모델에게 보이지도 않음
dogent mcp list | test [이름] | on|off 이름 | remove 이름
dogent mcp allow|ask|deny 서버 도구|*         # 도구 권한
dogent mcp keyword 서버 재공 Lot              # 요청 라우팅 키워드

8-3. 스킬에서 MCP 도구 쓰기

2. call_tool로 P1 라인 Lot 목록을 가져온다. args는 다음을 그대로 쓴다.
   `{"name": "mes.lot_list", "args": {"line": "{line}"}, "dataset": "lots"}`

결과가 JSON 객체 배열(또는 rows/data/items 안의 배열)이면 dataset에 표로 담겨 transform·write_excel·fill_table로 이어집니다. 도구 결과 안의 지시문은 따르지 않도록 프롬프트가 막고 있습니다.

8-4. 스킬(npx skills add) 주소 붙여넣기

현재는 인식만 하고 설치하지 않습니다 (데스크탑에서 "준비 중" 안내). 지금은 팀 스킬 저장소(dogent sync) 또는 말로 스킬 만들기를 쓰세요. §11의 P1 항목입니다.

  1. 확장을 빌드·로드하고 pnpm bridge:token으로 토큰 확인 (처음 실행 시 ~/.dogent/bridge-token 생성).

10. 미완 항목과 알려진 문제

10-1. e2e 실패(수정함): "MCP 서버" 시나리오 수정됨

pnpm e2e:client 15개 중 1개가 실패합니다. 요청 "mock-mes에서 P1 재공 목록 확인해줘"가 의도한 "브라우저 없이 MCP 도구만" 경로가 아니라 "지금 브라우저 화면에서 자유 요청" 경로로 갔습니다(결과는 MCP 도구로 정상 처리됨). 실행 결과에 시스템: 팀 MES, 모의 MES가 먼저 찍힌 것으로 보아, 시스템 사전이 "MES"를 시스템으로 인식해 officeIntent(..., hasSystem: true)가 web을 켜고, toolsOnly 조건(!intent.web)이 깨진 것으로 보입니다 (client/src/session.ts 약 640~652행). 서버 이름이 시스템 별칭과 겹칠 때 어느 쪽이 이길지 규칙을 정해야 합니다. 예: 요청에 MCP 서버가 명시되고 URL/화면 단서가 없으면 시스템 이름만으로는 web으로 보지 않기.

10-2. 설계 문서상 미구현

  • delegate(읽기 전용 자식 자유 요청), skill_ref/refs/, 도구 묶음 — docs/13 §3~4.
  • lint: run_skill id 존재·입력 이름·순환 검사 (현재는 깊이 1 제한이 순환을 막음).
  • 자유 요청은 지금 탭과 다른 사이트의 스킬을 run_skill 목록에 못 보여 줌.
  • 지연 로딩의 효과는 추정: 실모델(Gemma/Ollama)에서 전후 비교(llm_usage) 미실시. 본문은 30~55% 줄었지만 시스템 프롬프트(도구 설명 ≈3,800자)가 더 큼.
  • 예약은 CLI만 있음, EDM 스킬·xls·Hub·스크린샷 입력은 사내 확인 후 (docs/11-status.html §4).

10-3. 사내에서 확인되지 않은 것

항목위험확인법
사내 화면 호환성 (iframe, canvas 그리드, shadow DOM)큼확장의 "화면 점검" 보고서
사내 Gemma의 JSON·다단계 판단, 시스템 사전·MCP 안내를 따르는지큼조회 1건을 자유 요청으로 실행
NASCA가 Excel 저장본을 재암호화하는지중dogent excel resave 후 다른 PC에서 열기
Native Messaging·압축해제 설치 정책중dogent doctor, chrome://policy
사내 MCP 서버의 인증 방식(OAuth 등)·readOnlyHint 표기중실제 서버에 dogent mcp test
공용 PC에서 포트 39217 충돌, 모델 API 키 공유중환경 조사

10-4. 작업 정리

수정 27개 + 신규 17개 파일이 한 브랜치에 미커밋입니다. 커넥터(client/src/mcp-*, connectors.ts, UI), 도구 레지스트리(external.ts, actions/loop), 서브에이전트(subagent.ts), 지연 로딩(planner/prompt/skill), 스타일 대폭 변경(style.css ±1,000줄)이 섞여 있어 리뷰와 되돌리기가 어렵습니다. 4개 안팎으로 나눠 커밋하길 권합니다. 또한 desktop.e2e.mjs는 이번에 돌리지 않았습니다.

11-3. 개선하면 좋은 점

  • 라우팅 규칙을 한 곳에: 지금 session.ts에서 엑셀/시스템/주소/MCP 단서를 순차 if로 판단합니다. 단서 → 실행 방식(엑셀만/MCP만/브라우저+α)을 표 하나로 정의하고 단위 테스트(조합 표)로 고정하면 이번 같은 충돌을 막습니다. 판단 결과를 사용자에게 "이렇게 이해했습니다: 브라우저 없이 MCP 사용"으로 한 줄 보여 주는 것도 좋습니다.
  • 커넥터 도구가 많을 때: 서버가 도구를 수십 개 내놓으면 시스템 프롬프트가 급증합니다. 키워드/이름 매칭으로 서버당 상위 N개만 노출하고, 나머지는 search_tools 도구로 찾게 하는 지연 로딩을 적용하세요 (docs/13의 L0~L3와 같은 사상).
  • 오류 메시지·진단: dogent doctor를 MCP 서버(기동 실패 이유, 인증 실패, 도구 0개)까지 넓히고, 데스크탑 커넥터 탭에 같은 진단을 보여 주세요.
  • 문서 체계: 이 문서·docs/11-status.html·docs/13·README에 상태가 흩어져 있습니다. 기능이 바뀌면 11번(현황) 하나만 고치도록 하고, 이 문서의 §3~§8은 사용자용 매뉴얼로 DOGENT-GUIDE.html(pnpm guide:bundle)과 합치는 것을 검토하세요.
  • 데스크탑 UI 변경량: style.css ±1,000줄은 화면 전체 재디자인 수준입니다. 별도 PR로 분리하고 pnpm e2e:desktop을 통과시킨 뒤 병합하세요.
  • 성공 기준 수치화: 로드맵의 "20회 반복 성공률 90%"를 사내 모델로 재는 자동 스크립트(e2e:ollama의 사내판)를 두면 모델 교체·프롬프트 변경의 회귀를 바로 압니다.
