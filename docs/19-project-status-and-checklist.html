Dogent 구현 현황과 사내 확인 목록

기준일 2026-11-03 · 저장소 main (G1 반영: 공용 시스템 사전 연결) · 코드·문서를 직접 읽고, 단위 시험(pnpm test)과 타입 검사(pnpm typecheck)를 오늘 다시 돌려 확인함

1. 한눈에 보기

465 / 465단위·통합 시험 통과 (56개 파일, 2026-11-03 실행). 타입 검사 오류 없음
0건사내 실제 화면·사내 Gemma에서 검증한 항목. 모든 시험은 모의 사이트·모의 모델·로컬 Ollama·실제 Excel
4단계 완료확장 도구 서버 → 터미널 클라이언트 → 오피스 도구 → 데스크탑 앱 (docs/09). 그 위에 Claude Code·opencode 연계(docs/17 G1~G4)와 공용 시스템 사전
결론. 구조와 기능은 계획한 범위까지 만들어졌고 모의 환경에서는 끝까지 돕니다. 지금 가장 큰 위험은 코드가 아니라 사내 환경에서 아직 한 번도 돌려 보지 못했다는 점입니다. 그래서 다음 일은 새 기능이 아니라 사내 PC에서 "확인 목록(11장)"의 P0 항목을 먼저 닫는 것입니다. 막히는 곳이 드러나면 그 결과에 따라 남은 기능의 순서를 정합니다.

이 문서를 읽는 법

표시뜻
구현·시험됨코드가 있고 자동 시험이 통과함 (모의 환경 기준)
사내 미검증구현되어 있지만 사내 환경에서 확인하지 못함. 실제로 되는지는 모름
연결 미흡각각은 있는데 서로 이어지지 않았거나 설계와 구현이 어긋남
미구현아직 만들지 않음

가장 먼저 알아야 할 5가지

  1. 사내 검증이 전혀 없다. iframe·canvas 그리드·shadow DOM 같은 화면 구조, 사내 Gemma의 JSON 출력과 다단계 판단, 크롬 정책이 모두 미확인입니다. 확장의 화면 점검과 조회 1건 실행이 첫 관문입니다.
  2. 사내 업무 스킬이 아직 없다. 번들된 스킬은 범용 4개(화면 요약, 표→엑셀, 사이트 검색, 양식 채우기)뿐이고, 재공·방화벽 등 업무 스킬은 모의 사이트용 샘플입니다. 실제 시스템 스킬은 사내에서 녹화·말로 만들기로 새로 만들어야 합니다.
  3. 시스템 사전은 공용 서버를 정본으로 받아 쓴다. dogent config systemsUrl을 주면 앱·터미널이 공용 사전 서버에서 사전을 받아 로컬 사전(공용)으로 씁니다. 아직 실제 서버를 사내에 띄워 본 적은 없습니다 (6장, 10장 G1 해결).
  4. 문서 보안(NASCA)·EDM은 실제 환경을 못 봤다. 오피스 도구는 Excel COM으로 동작을 확인했지만, 재암호화 여부와 EDM 버튼 동작은 사내 확인이 필요합니다.
  5. 운영 도구(Hub)가 없다. 정책 배포, 실행 기록 수집, 중지 스위치, 사용량 확인이 없어서 여러 명이 쓰기 시작하면 현황을 볼 수 없습니다. 실행 기록은 각자 PC의 ~/.dogent에만 있습니다.

2. 전체 구성

3-2. 데스크탑 앱 (Electron)

  • 터미널 클라이언트와 같은 세션 엔진에 화면을 입힌 것. 스킬 폴더·설정·기록이 같음 (%USERPROFILE%\.dogent).
  • 화면: 스킬 찾기(맨 위 "지금 화면"), 스킬 목록, 시스템 탭, 말로 스킬 만들기, 열린 엑셀 문서, 대화(실행 카드·승인 안내·결과), 설정(확장 연결 토큰, 사용자 ID, 브라우저, 저장 폴더, 팀 스킬 폴더).
  • 앱이 시작할 때 크롬·엣지 프로필에서 확장을 찾아 Native Messaging 호스트를 자동 등록. 크롬과 엣지가 함께 붙으면 골라 씀.
  • 배포 형태: 압축을 푼 폴더 app\Dogent.exe (한 파일 실행본은 호스트로 응답하지 않는 문제로 폐기, 커밋 c39a666).
  • 상태: 구현·시험됨 (pnpm e2e:desktop) / 프로필 자동 탐지는 실제 프로필 미확인

3-3. 터미널 클라이언트

  • 명령: 말로 요청, run(스킬 직접), skills search/info, skill new/edit, check, systems, schedule, sync, doctor, excel, memory, agents, ask, serve, mcp add/import.
  • 맞는 스킬이 있으면 입력값을 뽑아 실행, 없으면 자유 요청(지금 화면에서 말로 시킴) → 잘 되면 개인 스킬로 저장.
  • 이어지는 대화 (최근 5차례와 결과 파일·데이터셋), DOGENT.md 지침("기억해: …"), 예약 실행(Windows 작업 스케줄러, 저장·상신은 하지 않음).
  • doctor: 확장이 안 붙을 때 토큰·포트·호스트 등록·회사 정책·실시간 연결을 점검 (--fix로 호스트 등록).
  • 상태: 구현·시험됨 / 예약의 실제 실행은 미확인

3-4. 오피스 도구 (dogent-office.exe)

  • 사용자의 Excel을 COM으로 부려 열기·읽기·쓰기·저장·닫기. 도구: excel_open / new / read / write / save / close / user_workbooks / attach. Visual Studio·SDK 없이 윈도우 기본 C# 컴파일러로 빌드.
  • EDM: 링크의 "읽기·편집"으로 Excel이 연 문서를 excel_attach로 잡아 읽고 열린 곳에 저장. 사용자 문서는 닫지 않고 놓기만 하고, 다른 이름 저장은 사본만 만듦.
  • 스킬의 엑셀 입력은 먼저 직접 읽고, 안 되면(보안 파일, xls) Excel로 엶.
  • 상태: 실제 Excel로 구현·시험됨 / NASCA 재암호화·EDM 버튼 동작은 사내 미검증

4. 사용 흐름

4-1. 말로 시키는 기본 흐름

  1. 사용자가 앱(또는 dogent "…")에 요청: "7라인 재공 확인해줘".
  2. 클라이언트가 요청에서 시스템 이름을 찾아 시스템 설명을 모델에 함께 보여 줌 (스킬 폴더의 systems/ 기준).
  3. 맞는 스킬을 골라 입력값을 뽑음. 없으면 자유 요청으로 현재 화면에서 수행.
  4. 필요하면 확인 후 새 탭에서 시작 (이미 열린 탭이 있으면 그 탭을 씀).
  5. 루프: 화면 읽기 → 모델 판단(또는 녹화된 빠른 경로) → 정책 검사 → 확장이 실행. 로그인 화면이면 멈추고 사람이 로그인.
  6. 저장·상신 단계면 브라우저에 승인 창이 뜨고, 사람이 승인해야 누름 (시험 실행이면 직전에 멈춤).
  7. 결과: 엑셀/HTML 보고서를 저장 폴더(기본 내려받기)에 저장하고 "폴더에서 보기"로 안내. 잘 된 자유 요청은 "스킬로 저장" 가능.

4-2. 대표 시나리오

조회 (R1)
"7라인 재공 확인" → 재공 화면 조회 → 페이지 넘기며 추출 → 가공 → 엑셀(원본/정체Lot/공정별집계). 저장·상신 없음이라 승인 창 없음.
신청 (R3, 승인 필요)
"IP 방화벽 해제 신청" → 입력값 정책 검사(IP 대역·금지 값) → 신청서 채움 → 화면 값과 입력값 대조 → 승인 창 → 상신. 시험 실행이면 상신 직전 중단.
엑셀 → 웹 일괄 입력
xlsx를 읽어(보안 파일이면 Excel로) 전체 검사 → 입력 → 저장 전 대조 → 승인. 행마다 같은 스킬을 돌리는 "묶어 실행"은 행별 승인과 행별 결과 엑셀.
여러 도구 섞기
"MES에서 7라인 재공 내려받아 클로드코드로 공정별 분석" → Dogent가 화면에서 내려받고 → claude.ask로 분석 위임. 반대로 Claude Code가 dogent_request로 사내 웹 부분만 맡김.

4-3. 안전장치 요약

5-3. 스킬 배포 (확장·앱 재배포 없이)

  1. 사내 GitHub에 dogent-skills 저장소를 만들고 templates/dogent-skills를 올림.
  2. 스킬을 PR로 더하고 CI 품질 검사 + 담당자 승인 → main.
  3. pnpm skill:index로 index.json(파일 해시 포함)을 만들어 게시.
  4. 빌드 설정 WXT_SKILLS_URL=https://…/raw/main/skills/index.json (비공개면 WXT_SKILLS_WITH_LOGIN=true). 앱·터미널은 teamSkillsUrl로 1시간마다 받아 [팀]으로 표시.
  5. 해시 불일치·품질 오류 스킬은 받지 않고 이유를 보여 줌. 스킬이 조작할 수 있는 사이트는 여전히 사이트 허용 목록 안.
주의. 저장소에 올릴 수 있는 사람이 곧 모든 사용자의 스킬을 바꿀 수 있는 사람입니다. main 보호, 쓰기 권한 제한, CODEOWNERS를 반드시 거세요.

6. 시스템 사전 (공용 서버 + 로컬)

모델은 "구글"은 알아도 "재공 시스템"은 모릅니다. 시스템 사전은 사내 시스템의 이름·별칭·주소·화면(메뉴 경로)·용어·주의사항을 적어 요청에 시스템 이름이 나오면 모델에 함께 보여 주는 문서(SYSTEM.md)입니다. 사전이 놓이는 곳은 두 군데이고, 공용 서버가 정본입니다. 클라이언트는 공용 서버에서 받아 로컬 캐시(~/.dogent/systems-cache)로 두고, 같은 id는 개인 > 공용 > 팀 > 기본 순서로 씁니다.

A. 로컬 사전 (개인·팀·기본)B. 공용 사전 서버 (정본, templates/dogent-systems)
위치<스킬 폴더>/systems/<id>/SYSTEM.md — 개인 > 팀(팀 스킬 저장소) > 기본사내 GitHub dogent-systems 저장소 → 사내 서버의 MCP 서버(systems-mcp.mjs)
클라이언트가 쓰는 방식자동: 요청에서 이름을 찾아 설명을 요청 해석·자유 요청에 주입, 화면이 없으면 주소를 열지 물음, 앱의 시스템 탭자동(받아서 로컬로): dogent config systemsUrl http://서버:8787 → 서버의 GET /systems.json을 받아 A와 같은 경로로 주입 (공용으로 표시). 다른 도구는 mcp add로 붙여 모델이 find_system 등을 호출
품질 관리팀 스킬 저장소의 CI/리뷰에 의존전용 검사기(형식, 폴더=id, 주소⊂domains, 이름·별칭 중복), CODEOWNERS 부서별 승인, status verified/draft, report_issue 신고
반영 속도1시간 간격(팀 스킬 동기화)서버가 --pull 주기(예 5분)마다 main을 받고, 클라이언트는 1시간마다(앱은 켤 때도) 판 번호(ETag)로 확인해 바뀐 때만 받음
사용하는 도구Dogent 클라이언트·앱Dogent, opencode, Claude Code 모두 같은 답
연결됨 (G1). 두 길의 파일 형식은 같고(SystemMeta), 클라이언트가 공용 서버를 받아 로컬 캐시로 씁니다. 서버가 꺼져 있어도 마지막으로 받아 둔 것으로 돕니다. 한 시스템을 팀 스킬 저장소의 systems/에도 따로 적지 마세요. 같은 id가 있으면 공용이 앞서지만, 사람이 어느 쪽을 고쳐야 하는지 헷갈립니다. 서버가 토큰을 쓰면 각자 dogent config systemsToken을 넣어야 합니다.

운영 방법(저장소 만들기, 담당자, 서버 띄우기, 신고 처리)은 docs/18-systems-dictionary-guide.md에 있습니다.

7. 사내 전용 시스템 연결 순서

새 사내 시스템(예: GSAMS)을 Dogent가 다루게 하려면 아래 순서로 한 단계씩 닫습니다. 앞 단계가 막히면 뒤는 의미가 없으므로 순서대로 확인하세요.

  1. 설치와 연결 — 배포 묶음 release\Dogent-company-<판>\install.cmd → 앱과 확장 설치 → 앱 위쪽에 브라우저 이름이 뜨는지. 안 뜨면 dogent doctor.
  2. 모델 연결 — 확장 패널 → 설정 → 사용자 ID → 연결 시험이 "연결됨". 브라우저가 주소 접근을 막으면 이 주소 접근 허용.
  3. 사이트 허용 — 업무 화면에서 패널 위쪽 화면 점검 → 허용 목록에 없으면 이 사이트 허용. (SSO·로그인 호스트나 리다이렉트되는 호스트도 필요할 수 있음)
  4. 화면 읽힘 확인 — 화면 점검 보고서에서 iframe·canvas 그리드·shadow DOM·머리글 없는 표를 확인. 보고서(.md)는 값·글자를 가려 사내 밖으로 공유 가능.
  5. 조회 1건 — 자유 요청으로 "이 화면에서 7라인을 조회해서 몇 건인지 알려줘" 실행. 성공하면 "스킬로 저장".
  6. 시스템 사전 등록 — systems/<id>/SYSTEM.md 작성(별칭이 핵심). 공용 저장소 PR → 검사 → 담당자 승인 (6장).
  7. 스킬 만들기 — 말로 만들기 또는 녹화 → 품질 B 이상 → 시험 실행 통과 → 팀 저장소 PR.
  8. 쓰기 업무 — 반드시 시험 실행으로 상신 직전 멈춤 확인 → 승인 창 내용이 화면 값과 같은지 확인 → 실제 상신. 입력값 정책(policy.yaml)을 업무 규칙에 맞게 작성.
  9. 반복 측정 — 같은 시나리오 20회 반복 성공률(목표 90%), 추출값이 화면과 100% 일치하는지 확인.
  10. 엑셀 연계 — 내려받은 파일 형식(xlsx/xls/csv)과 NASCA 여부 확인 → 필요하면 saveThroughExcel.

시스템별 사전 작성 최소 항목

---
id: gsams                      # 폴더 이름과 같게, 영문 소문자·숫자·하이픈
name: GSAMS
description: IP 방화벽 정책 등 접근 권한을 신청·결재하는 사내 시스템
aliases: [GSAMS, 지삼스, 방화벽 신청]   # 사람들이 실제로 부르는 말 (가장 중요)

screens:

10-1. 연결·구조

#내용왜 문제인가제안심각도
G1해결 시스템 사전 이원화. 공용 사전 서버의 내용이 클라이언트의 자동 주입(요청 해석·자유 요청·"주소 열까요?")에 쓰이지 않음. docs/17은 "모두 → 시스템 사전"이라고 적었지만 클라이언트 코드에는 공용 서버를 부르는 곳이 없음 (docs/17 P2-4로 남아 있음)공용 사전을 아무리 잘 관리해도 Dogent 앱의 시스템 인식에는 반영되지 않음. 같은 시스템을 두 곳에 적게 되어 어긋남구현함: systemsUrl 설정(빌드의 WXT_SYSTEMS_URL)으로 공용 서버의 /systems.json을 받아 ~/.dogent/systems-cache에 두고 '공용'으로 읽음 (개인 > 공용 > 팀 > 기본). 서버가 안 닿으면 받아 둔 것 사용. 정본은 공용 저장소 하나해결
G2배포 채널이 둘. 스킬은 dogent-skills 저장소, 사전은 dogent-systems 저장소(또는 팀 스킬 저장소의 systems/)어디가 정본인지 사람마다 다르게 이해할 수 있음. 스킬이 사전의 화면 정보를 참조할 때 버전이 어긋남정본 위치를 문서로 못 박고, 시스템 폴더가 스킬을 가리키는 규칙(screens·스킬 id)을 검사기에 추가중간
G3사내 업무 스킬 0개. 샘플은 모의 사이트용사내에서 켰을 때 쓸 수 있는 업무가 없음. 시험을 기다리게 됨첫 업무 2건(조회 1, 쓰기 1)을 현업과 정하고, 화면 점검 → 말로 만들기 → 시험 실행으로 먼저 하나 완성높음
G4Hub 없음. 정책 배포, 실행 기록 수집, 중지 스위치(kill switch), 사용량·성공률 통계가 없음여러 명이 쓰면 문제가 생겨도 알 수 없고 한꺼번에 멈출 수 없음. 실행 기록은 PC마다 로컬이라 감사에 쓰기 어려움최소안: 실행 기록 요약을 사내 서버에 보내는 선택 기능 + 팀 스킬 저장소에 "금지 스킬 목록"을 두는 중지 방법. 서버 위치·인증·운영 주체를 먼저 결정중간 (파일럿 전에는 높음)
G5모델 키가 빌드에 들어가 모두 같은 키. 사용자 구분은 user-id 헤더뿐빌드 파일을 가진 사람은 키를 꺼낼 수 있음. 사용자별 사용량·차단 불가개인 토큰 발급 가능 여부 확인 → 가능하면 설정의 개인 키 사용. 아니면 사내 중계 서버(Hub)가 키를 붙이는 구조높음 (보안 협의)
G6기본 빌드가 모든 http·https 사이트에 접근 권한을 선언 (WXT_ALL_SITES 기본 참). 예시 파일에도 이 키가 없음보안 검토에서 "모든 사이트 읽기·변경" 권한으로 보임. 설계 원칙 D6(조작할 사이트 목록)과 느낌이 다름보안 부서와 협의: 회사 프록시가 막는다는 가정이 받아들여지는지, 아니면 WXT_ALL_SITES=false + 사내 도메인 목록으로 시작. 예시 파일에 키와 설명 추가높음
G7포트 39217이 PC에 하나. 공용 PC·원격 데스크톱에서 두 번째 사용자가 못 뜸사용자별 브리지 충돌공용 PC가 있는지 먼저 확인. 있으면 사용자별 포트 또는 Native Messaging 전용 사용중간
