# 01. 유즈케이스 정의서

> 프로젝트 가칭: **Dogent** — 사내 Gemma 기반 브라우저·업무 에이전트
> 문서 상태: 초안 (v0.1, 2026-10-13)
> 시스템명·화면명은 가정입니다. 실제 대상 시스템이 정해지면 치환합니다.

## 1. 액터

| 액터 | 설명 |
|---|---|
| 현업 사용자 | 에이전트에게 업무를 지시하고 결과를 확인·승인하는 엔지니어/담당자 |
| 스킬 작성자 | 업무 SOP를 스킬 문서로 작성·수정하는 현업 파워유저 또는 PI 담당 |
| 스킬 검토자 | 스킬을 리뷰하고 배포를 승인하는 업무 오너 |
| 운영자 | 확장/클라이언트 배포, 정책(허용 도메인 등), 로그를 관리하는 담당 |
| 기존 결재권자 | 방화벽 신청 등 기존 시스템의 승인자. **에이전트 도입 후에도 역할이 바뀌지 않음** |

## 2. 위험 등급

모든 동작은 아래 등급으로 분류하며, 스킬은 자신이 쓰는 최고 등급을 선언합니다.

| 등급 | 동작 | 통제 |
|---|---|---|
| R0 | 조회, 화면 읽기, 데이터 추출, 조회 조건 입력 | 자동 실행 |
| R1 | 로컬 파일 생성·저장 | 자동 실행, 저장 위치 고지 |
| R2 | 저장 대상 업무 데이터를 웹 화면에 입력 (저장 전) | 자동 실행, 입력 결과 미리보기 제공 |
| R3 | 저장, 상신, 제출, 삭제 등 되돌리기 어려운 동작 | **사용자 승인 필수**, 감사 로그 기록 |

## UC-01. 재공(WIP) 확인

**목적**: 담당 라인/공정/제품의 재공 현황을 조회하고 정체 Lot 등 확인 포인트를 정리한다.

**현재 방식**: 재공 조회 화면 접속 → 조건 입력 → 조회 → 그리드를 눈으로 확인하거나 엑셀로 내려받아 필터링.

**사전 조건**: 사용자가 해당 시스템에 로그인되어 있고 조회 권한이 있다.

**기본 흐름**

1. 사용자가 사이드 패널에 "8라인 PHOTO 공정 재공 확인해줘"라고 입력한다.
2. 에이전트가 `재공 확인` 스킬을 선택하고, 부족한 입력(제품군 등)이 있으면 되묻는다.
3. 재공 조회 화면으로 이동하고 조건을 입력한 뒤 조회한다.
4. 결과 그리드를 추출한다. 페이지가 여러 개면 끝까지 수집한다.
5. 스킬에 정의된 기준(예: 정체 시간 임계값)으로 로컬에서 필터·집계한다.
6. 요약(총 재공, 공정별 수량, 기준 초과 Lot 목록)을 패널에 표시하고 엑셀로 저장한다.

**대안/예외 흐름**

- 조회 결과 0건: 조건을 그대로 보여주고 종료한다. 임의로 조건을 바꿔 재조회하지 않는다.
- 세션 만료: 로그인 화면을 감지하면 중단하고 사용자에게 로그인을 요청한다. 계정 정보를 에이전트가 입력하지 않는다.
- 화면 구조 변경으로 요소를 못 찾음: 모델이 화면을 다시 읽어 복구를 1회 시도하고, 실패하면 현재 화면과 함께 중단 보고한다.

**결과물**: 패널 요약, 엑셀 파일(원본 시트 + 요약 시트).

**성공 기준**: 동일 조건 20회 반복 시 성공률 90% 이상, 추출 데이터가 화면 값과 100% 일치.

## UC-02. 웹 → 엑셀 내보내기 및 가공

**목적**: 웹 시스템의 조회 결과를 엑셀로 가져와 정해진 양식으로 가공한다.

**기본 흐름**

1. 사용자가 대상 화면과 조건, 원하는 가공 형태를 지시하거나 스킬을 호출한다.
2. 에이전트가 조회 후 데이터를 확보한다. 우선순위는 ① 화면의 엑셀 다운로드 버튼 ② 그리드 직접 추출.
3. 에이전트가 **가공 명세**(필터, 정렬, 그룹 집계, 컬럼 파생, 조인)를 작성한다.
4. 로컬 변환 엔진이 명세를 실행한다. 모델이 숫자를 직접 계산하지 않는다.
5. 결과를 미리보기(상위 N행, 행 수, 합계 검증)로 보여주고 엑셀로 저장한다.

**예외**

- 다운로드 파일 형식이 예상과 다름(컬럼 누락 등): 차이를 보고하고 중단한다.
- 가공 결과의 행 수·합계가 원본과 맞지 않음: 검증 실패로 표시하고 저장하지 않는다.

**설계 원칙**: 대량 데이터는 모델에 보내지 않는다. 모델에는 컬럼 구조와 샘플 몇 행만 전달하고, 실제 데이터는 PC 안에서만 처리한다.

## UC-03. 엑셀 → 웹 일괄 입력(붙여넣기)

**목적**: 엑셀로 정리한 데이터를 웹 화면의 그리드나 폼에 일괄 입력한다.

**기본 흐름**

1. 사용자가 엑셀 파일(또는 범위)과 대상 화면을 지정한다.
2. 에이전트가 엑셀 컬럼과 화면 필드를 매핑하고 매핑표를 사용자에게 보여준다.
3. 입력 전 데이터 검증(필수값, 형식, 코드값)을 수행하고 오류 행을 표시한다.
4. 입력을 실행한다. 방식은 화면에 따라 선택한다.
   - 그리드가 엑셀 붙여넣기를 지원: 클립보드 일괄 붙여넣기
   - 미지원: 행 단위 셀 입력
   - 화면에 업로드 기능이 있음: 업로드 양식으로 변환 후 업로드
5. 입력된 화면 값을 다시 읽어 엑셀 원본과 대조한다.
6. 대조 결과와 함께 **저장 승인을 요청**한다(R3). 승인 시 저장한다.

**예외**

- 일부 행 입력 실패: 실패 행 목록을 보고하고 저장하지 않는다. 부분 저장은 사용자가 명시적으로 선택한 경우만 허용한다.
- 저장 후 서버 오류 메시지: 메시지 원문을 그대로 보고한다.

**성공 기준**: 입력 후 대조 일치율 100%일 때만 저장 승인 요청이 뜬다.

## UC-04. 다중 시스템 데이터 결합 리포트

**목적**: 둘 이상의 시스템 데이터를 결합해 리포트를 만든다(예: 재공 현황 + 설비 상태).

**기본 흐름**

1. 스킬이 시스템별 조회 단계를 순서대로 수행해 데이터셋을 확보한다.
2. 결합 키(예: 설비 ID, Lot ID)로 조인하고 가공 명세를 실행한다.
3. 정해진 리포트 양식(엑셀 템플릿)에 채워 저장한다.

**비고**: 데스크탑 클라이언트가 필요하다(여러 탭/시스템 연계, 템플릿 파일 접근).

## UC-05. IP 방화벽 해제 신청

**목적**: 방화벽 정책 신청 사이트에 접속해 해제 신청서를 작성·상신하는 반복 작업을 줄인다.

**범위 한정**: 에이전트는 **신청서 작성과 상신까지만** 대행한다. 승인은 기존 결재 라인이 그대로 수행하며, 에이전트가 승인 절차를 대신하거나 우회하지 않는다.

**기본 흐름**

1. 사용자가 "개발서버 10.x.x.x에서 DB 10.y.y.y 1521 포트, 3개월 해제 신청해줘"처럼 지시하거나, 여러 건이 담긴 엑셀을 지정한다.
2. 에이전트가 필수 항목(출발지, 목적지, 포트/프로토콜, 기간, 사유)을 확인하고 빠진 항목을 되묻는다.
3. 로컬 검증을 수행한다: IP/포트 형식, 금지 패턴(전체 대역, any 포트, 최대 기간 초과 등 정책 파일에 정의).
4. 신청 사이트에 접속해 신청서를 작성한다.
5. 작성된 화면 값을 다시 읽어 요청 내용과 대조하고, 요약과 함께 **상신 승인을 요청**한다(R3).
6. 승인 시 상신하고 신청 번호를 기록한다.

**예외**

- 검증 위반: 사이트에 접속하기 전에 중단하고 위반 항목을 알려준다.
- 사유가 비어 있거나 모호함: 모델이 사유를 지어내지 않고 사용자에게 요청한다.
- 동일 내용의 기존 신청이 조회됨: 중복 가능성을 알리고 사용자 판단을 받는다.

**통제 사항**

- 상신은 건별 승인이 기본이다. 일괄 승인은 운영 정책으로 허용한 경우에만 쓴다.
- 신청자, 일시, 신청 내용, 신청 번호를 감사 로그에 남긴다.
- 이 유즈케이스는 보안 부서와 사전 협의 후 진행한다.

## UC-06. 정기 실행(스케줄) 리포트

**목적**: 매일/매주 같은 조회·가공을 정해진 시각에 실행한다.

**기본 흐름**

1. 사용자가 스킬과 입력값, 주기를 등록한다.
2. 데스크탑 클라이언트가 시각에 맞춰 실행한다. PC와 브라우저가 켜져 있고 로그인 상태여야 한다.
3. 결과 파일을 지정 폴더에 저장하고 완료를 알린다.

**제약**: R0~R1 스킬만 스케줄 등록할 수 있다. 승인이 필요한 동작은 무인 실행하지 않는다.

---

## UC-07. 스킬 작성·검토·배포

**기본 흐름**

1. 작성자가 템플릿으로 스킬 문서를 작성한다(또는 사용자의 실제 조작을 녹화해 초안을 생성 — Phase 3).
2. 로컬에서 테스트 실행한다(드라이런: R3 동작은 실행 직전에 멈춤).
3. 사내 Git 저장소에 변경 요청을 올리고, 검토자가 승인한다.
4. 병합되면 사용자 PC가 다음 동기화 때 새 버전을 받는다.
